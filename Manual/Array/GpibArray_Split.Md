# コマンドリファレンス：Array_Split

## 概要
`Array_Split` は、二次元配列バッファから指定された矩形範囲（開始位置と切り出し個数）を切り出し（スライス）、別の変数へ格納する配列バッファ操作系コマンドです。
主に、計測器から一括受信した巨大なデータ行列から、特定のチャンネル成分や特定の時間軸範囲だけをピンポイントで抽出・分離して解析用変数に割り当てる用途に使用します。

> 💡 **補足 / ⚠️ 注意**
> 切り出し指定範囲が元データの実際のサイズを超えてはみ出した場合、はみ出した領域が「空文字」として安全に自動補完され、システムクラッシュを防止するセーフティガード仕様を持っています。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], Array_Split, [格納先変数], [元データ変数], [X軸範囲], [Y軸範囲], [区切り文字]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 格納先変数 | 切り出した矩形配列バッファを新しく格納するための変数名。 | `PARAM` であらかじめ定義した `Work` 型の変数キー名 |
| **引数2** | 元データ変数 | 切り出し元となるデータが格納されている二次元配列の変数名。 | `PARAM` であらかじめ定義した `Work` 型の変数キー名 |
| **引数3** | X軸範囲 | 列方向の切り出し「開始インデックス-個数」を定義する文字列。 | 二重引用符で囲み `"開始-個数"`（例: `"1-2"`） |
| **引数4** | Y軸範囲 | 行方向の切り出し「開始インデックス-個数」を定義する文字列。 | 二重引用符で囲み `"開始-個数"`（例: `"0-2"`） |
| **引数5** | 区切り文字 | 配列をパース・再結合する際に使用する要素同士のデリミタ。 | カンマを指定する場合は必ず `","` で囲む。半角スペースは `" "`（半角スペース1文字）を直接入力します。 |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: 引数内で `$PARAMキー$` のようにパラメータキーの両端を `$` で囲むと、実行時に `PARAM` の値へと動的置換されます。（適用可能な引数：引数3、引数4、引数5）
    *   *応用*: 範囲指定の引数内で `$P_START$-1` のように組み合わせることも可能です。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません。
*   **カンマのエスケープ**: 引数5の区切り文字にカンマを指定する場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述します。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください。

```csv
COMMAND, "Extract_Channel"
; データ領域変数をそれぞれ定義
,PARAM, BIG_DATA, Work, "大容量受信データ"
,PARAM, CH1_ONLY, Work, "CH1抽出結果格納用"
; 1列目から2列分、0行目から2行分をカンマ区切りで切り出す
,SEQUENCE, 30, Array_Split, CH1_ONLY, BIG_DATA, "1-2", "0-2", ","
```

### 実行時の挙動・変数変化

#### 例1：多チャンネルデータから特定範囲（2列目以降の2列×2行）を抽出
*   **実行前の状態**: 変数 `BIG_DATA` に4列×3行のデータがカンマ区切りテキストとして格納されている状態。
    ```text
    A,B,C,D
    E,F,G,H
    I,J,K,L
    ```
*   **実行後の状態**: 0ベースのインデックスから、指定された矩形範囲（B, CおよびF, Gの領域）がスライスされ、変数 `CH1_ONLY` に以下のテキストとして格納されます。
    ```text
    B,C
    F,G
    ```

#### 例2：切り出し指定範囲が元データの実際のサイズを超えてはみ出した場合
*   **スクリプト例**: `,SEQUENCE, 40, Array_Split, CH1_ONLY, BIG_DATA, "1-2", "1-3", ","`
*   **実行前の状態**: 例1と同じ4列×3行の `BIG_DATA` を使用。
    ```text
    A,B,C,D
    E,F,G,H
    I,J,K,L
    ```
*   **実行後の状態**: 縦方向のインデックス1（2行目）から3行分を抽出する際、4行目は存在しないため「セーフティガード」が自動発動します。はみ出した領域が「空文字」として安全に自動補完され、システムクラッシュを防止します。
    ```text
    F,G
    J,K
    ,
    ```

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。

*   **ハイフン区切りのフォーマットが不正・数値変換に失敗した場合**
    引数3・引数4に指定された文字列が `[開始]-[個数]` の形式として正しくパースできない場合（例: `"3"`, `"1-2-3"`）、または `"0-A"` などの非数値が混入した場合、あるいは開始位置がマイナス（0未満）や個数が0以下の場合は、内部エラーログに内容を出力し、データの破壊を防ぐために処理を行わずに該当ステップを安全にスキップ（早期リターン）します。
*   **存在しない変数キーを引数1または引数2に指定した場合**
    引数1（格納先）または引数2（元データ）で指定された変数名が、あらかじめ定義された変数プール（`PARAM`）に存在しない場合、エラーログを出力して処理を安全に中断し、システム全体の強制終了（例外発生）を自動防御します。

* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

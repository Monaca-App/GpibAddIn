# コマンドリファレンス：Array_Set

## 概要
`Array_Set` は、二次元配列バッファの特定のインデックス（X, Y座標）を指定し、値を安全に上書きセットする配列バッファ操作系コマンドです。
主に、`Array_Init` で初期化した領域や外部から取得したデータグリッドに対して、特定のセルを指定して計測値や解析結果を個別に書き込む用途に使用します。

> 💡 **補足 / ⚠️ 注意**
> 指定座標が現在の配列長を超えている場合は自動拡張（リサイズ）され、不足するセルはデリミタ（区切り文字）で自動補完される強力な動的拡張仕様を持っています。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], Array_Set, [対象変数], [X軸インデックス], [Y軸インデックス], [区切り文字], [設定値]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 対象変数 | 値を書き込む対象となる二次元配列が格納された変数名。 | `PARAM` であらかじめ定義した `Work` 型の変数キー名 |
| **引数2** | X軸インデックス | 書き込み先セルの横方向の位置（0オリジンの列番号）。 | 固定値（例: `0`）またはパラメータ動的置換（例: `$P_X$`） |
| **引数3** | Y軸インデックス | 書き込み先セルの縦方向の位置（0オリジンの行番号）。 | 固定値（例: `10`）またはパラメータ動的置換（例: `$P_Y$`） |
| **引数4** | 区切り文字 | 配列を解析・再構成する際に使用する要素同士のデリミタ。 | カンマを指定する場合は必ず `","` で囲む。半角スペースは `" "`（半角スペース1文字）を直接入力します。 |
| **引数5** | 設定値 | 指定したセルに新しく上書きセットする文字列または数値。 | 固定値（例: `"12.34"`）またはパラメータ動的置換（例: `$V_MEAS$`） |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: 引数内で `$PARAMキー$` のようにパラメータキーの両端を `$` で囲むと、実行時に `PARAM` の値へと動的置換されます。（適用可能な引数：引数2、引数3、引数4、引数5）
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません。
*   **カンマのエスケープ**: 引数4の区切り文字自体にカンマを含める場合や、引数5の設定値にカンマを含む文字列を指定する場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述します。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください。

```csv
COMMAND, "Set_Array_Value"
; 配列を保持するワークエリアと、動的代入用の変数を定義
,PARAM, CH1_GRID, Work, "データグリッド領域"
,PARAM, P_INDEX_Y, Value, "書き込み行指定", "2"
; 配列の指定セル(0, 2)に「99.9」を書き込む
,SEQUENCE, 20, Array_Set, CH1_GRID, 0, $P_INDEX_Y$, ",", "99.9"
```

### 実行時の挙動・変数変化

#### 例1：既存のバッファ内へのピンポイント上書き（1列目、0行目）
*   **スクリプト例**: `,SEQUENCE, 10, Array_Set, CH1_GRID, 1, 0, ",", "NEW_DATA"`
*   **実行前の状態**: 変数 `CH1_GRID` にカンマ区切りの2列×2行の初期データが格納されている状態。
    ```text
    A,B
    C,D
    ```
*   **実行後の状態**: 0ベースのため、0行目の1列目（2列目）である `B` が `NEW_DATA` に安全に上書きされます。
    ```text
    A,NEW_DATA
    C,D
    ```

#### 例2：インデックスが配列サイズを超えた場合の「自動拡張」動作
*   **スクリプト例**: `,SEQUENCE, 20, Array_Set, CH1_GRID, 2, 1, ",", "BINGO"`
*   **実行前の状態**: 変数 `CH1_GRID` にカンマ区切りの1列×1行の初期データが格納されている状態。
    ```text
    A
    ```
*   **実行後の状態**: 存在しない「2行目の3列目（インデックス2, 1）」を指定したため動的拡張が発動。不足している行と列がカンマで自動補完され、ターゲットセルに正確に書き込まれます。
    ```text
    A
    ,,BINGO
    ```

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。

*   **非数値や負の数が入力された場合**
    引数2（X）、引数3（Y）に指定された文字列が整数に変換できない場合、または 0 未満のマイナス数値が指定された場合は、内部エラーログに内容を出力し、書き込みを行わずに該当ステップを安全にスキップ（早期リターン）します。メインシステムをフリーズさせません。
*   **存在しない変数キーを対象変数（引数1）に指定した場合**
    引数1で指定された変数名が、あらかじめ定義された変数プール（`PARAM`）に存在しない場合、エラーログを出力して処理を安全に中断し、システム全体の強制終了（例外発生）を自動防御します。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

| :--- | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `currentData = "A,B\r\nC,D"`<br>`xIdx = 1`, `yIdx = 0`<br>`delimiter = ","`<br>`val = "NEW"` | `"A,NEW\r\nC,D"` | 指定した有効なインデックス位置（0行目の1列目）の値が、指定値に正しく上書きされること。 |

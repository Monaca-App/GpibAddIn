# コマンドリファレンス：Equ

## 概要
`Equ` は、2つのパラメータ（変数値または固定文字列）を比較し、両者が「不一致（等しくない）」だった場合に、指定されたステップ番号へ制御をジャンプ（条件分岐）させる実行フロー・条件分岐系コマンドです [1.1]。
計測値が期待値と異なる場合の「リトライループ」の構築や、特定の判定フラグが立っていない場合の「エラー処理へのジャンプ」などのフロー制御に活用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドは、文字列としての大文字・小文字を区別しない一致判定（`OrdinalIgnoreCase`）を行います [1.1]。比較対象である「値1」と「値2」が等しくないときのみジャンプが発動し、一致している場合はジャンプせず次のステップへそのまま進みます [1.1]（例: `"true"` と `"TRUE"` は同一と判定されます）。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], Equ, [比較する値1], [比較する値2], [ジャンプ先ラベル名]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 比較する値1 | 比較対象となる1つ目の値 [1.1]。 | 固定文字列、またはパラメータ動的置換（例: `$P_STATUS$`） [1.1] |
| **引数2** | 比較する値2 | 比較対象となる2つ目の値 [1.1]。 | 固定文字列（例: `"1"` や `"OK"`）、またはパラメータ動的置換 [1.1] |
| **引数3** | ジャンプ先ラベル名 | 不一致の際に遷移する `SEQUENCE` のジャンプ先ラベル名（ステップキー） [1.1]。 | ジャンプ記法（例: `#10#` や `#Start#`）またはラベル名（例: `10` や `Start`）。省略時はマクロ終了 [1.1]。 |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです [1.1]。

*   **動的置換（`$`）**: 引数1および引数2において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.1]。
*   **条件ジャンプ（`#`）**: 引数3において、ターゲットとなるラベル名を `#10#` や `#Start#` のように `#` で囲んで指定することで、条件不一致時のジャンプ先として安全にバインドされます [1.1]。
*   **カンマのエスケープ**: 比較する文字列自体にカンマを含める場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Wait_For_Complete"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_STATUS, Text, "ステータス確認用バッファ", ""
; [10] 計測器にステータス確認コマンドを送信
,SEQUENCE, 10, Send, "STAT?"
; [20] 応答（例: 完了なら "1", 処理中なら "0"）をバッファに受信
,SEQUENCE, 20, Receive
,SEQUENCE, 30, SetData, P_STATUS, "%s"
; [40] 受信したバッファの値が "1" と不一致（＝まだ処理中）なら、ステップ10へ戻る
,SEQUENCE, 40, Equ, $P_STATUS$, "1", #10#
; [50] "1" と一致していれば、ジャンプせずにここへ進み次の処理へ
,SEQUENCE, 50, Send, "FETCH_DATA?"
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 機器の処理完了待機状態であり、現在の完了判定ステータスを格納するための変数 `P_STATUS` が確保されている状態です [1.2]。
*   **実行後の状態**: 変数 `P_STATUS` の中身が評価されます [1.1, 1.2]。値が `"1"` 以外（例: `"0"`）であれば条件不一致とみなされ、引数3で指定されたステップキー `#10#` へと実行フローが安全にジャンプ（ループ）します [1.1, 1.2]。値が `"1"` と一致した場合はジャンプが発生せず、そのまま次のステップ（ステップ50）へ進みます [1.1, 1.2]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **ジャンプ先（引数3）が省略または空（Null）の場合**
    ジャンプフラグ（`param.Jump`）を有効化した上で、マクロの末尾へ安全にジャンプさせ、処理を正常終了させます [1.2]。
*   **存在しないラベル名（ステップキー）が指定された場合**
    指定されたラベル名（または数値）が現在のマクロ内に存在しない場合、自動的にマクロの末尾へ安全に処理を遷移（マクロ終了）させることで、ハングアップを自動防御します [1.1, 1.2]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

### テストケース一覧

| No | テストカテゴリ | テスト条件（入力値） | 期待される結果（出力値） | 検証の目的 / 観点 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `val1 = "OK"`<br>`val2 = "OK"` | 戻り値: `true` | 両方の文字列値が完全に一致している場合に、正しく `true` と判定されること。 |
| **2** | 正常系 | `val1 = "OK"`<br>`val2 = "NG"` | 戻り値: `false` | 文字列値が一致しない場合に、正しく `false` と判定されること。 |
| **3** | 特殊系 | `val1 = ""`<br>`val2 = ""` | 戻り値: `true` | 空文字列同士を比較した場合に、正しく `true` と判定されること。 |
| **4** | 正常系 | `val1 = "TRUE"`<br>`val2 = "true"` | 戻り値: `true` | 大文字・小文字が異なる場合でも同一とみなし、正しく `true` と判定されること。 |

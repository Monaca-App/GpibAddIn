# コマンドリファレンス：ReadRegisterByte

## 概要
`ReadRegisterByte` は、Interface製ボードの物理レジスタから直接バイトデータを読み込む 物理層・デバイス制御系 コマンドです。
ボード上の各種状態レジスタや制御ポートの値を直接取得して確認する目的や、低レベルな制御デバッグに用いられます。

## 💡 書式・パラメータ仕様
```csv
,SEQUENCE, [ステップキー], ReadRegisterByte, [ボードID], [オフセット], [結果格納変数キー]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| 引数1 | ボードID | 対象とするGPIBボードの識別ID番号。 | 固定値（整数）、PARAM変数キー、動的置換が可能です。 |
| 引数2 | オフセット | 読み出し対象のレジスタのオフセットアドレス。 | 10進数または16進数（例: 0x04）、PARAM変数キー、動的置換が可能です。 |
| 引数3 | 結果格納変数キー | 読み出したバイト値（0〜255）を格納する変数のキー名。 | `@` で始まるPARAM変数キー（例: `@VAL`）を直接指定します。 |

## 🔄 特殊置換規約・分岐規約の適用
本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。
*   **動的置換（`$`）**: 引数内で `$PARAMキー$` のように記述すると、実行時に変数プール（PARAM）の値へ動的置換されます。（適用可能な引数：引数1、引数2、引数3）
*   **ジャンプ先指定（`#`）**: 本コマンドは分岐制御を行わないため、ジャンプ先指定は適用されません。
*   **共通コマンド指定（`@`）**: 外部マクロ名や機器を対象としないため、共通コマンド指定は適用されません。
*   **カンマのエスケープ**: 引数自体にカンマを含める場合は、必ず `","` と二重引用符で囲んで記述します。

## 💡 動作例（正しい構文での記述例）
### スクリプト記述例
※COMMANDブロック配下のため、子要素行（PARAM, SEQUENCE）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。

```csv
COMMAND, "ReadRegSample", ""
,PARAM, @BOARD_ID, Value, "ボード番号", "0"
,PARAM, @OFFSET, Value, "レジスタオフセット", "0x04"
,PARAM, @VAL, Value, "結果格納変数", "0"
,SEQUENCE, S001, ReadRegisterByte, $@BOARD_ID$, $@OFFSET$, @VAL
```

### 実行時の挙動・変数変化
*   **実行前の状態**: `@BOARD_ID` の値は `0`、`@OFFSET` の値は `0x04`、結果格納変数 `@VAL` の値は `0`。
*   **実行後の状態**: ボードID `0` のオフセットアドレス `0x04` のレジスタ値（例: `90`）が読み込まれ、結果格納変数 `@VAL` の値が `90` に更新されます。

## 🚫 エラーハンドリング・安全設計（仕様制限）
入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。
*   **非対応のドライバーがロードされている状態での呼び出し（仕様制限）**  
    本コマンドは Interface製ドライバー（`GPC4304.DLL`）専用の機能です。CONTEC製ドライバー（`CGPIB.DLL`）がロードされている動作環境で本コマンドが実行された場合、実行エンジンは「専用機能使用不可」の警告ログを出力し、物理層への通信を行わずに安全に早期正常終了（スキップ）してシステムフリーズを防ぎます。
*   **存在しない変数キーの指定**
    引数3（結果格納変数キー）に存在しないPARAM変数を指定した場合、エラーログを記録した上で変数更新処理をスキップし、例外による強制終了を自動防御します。
*   **引数パラメータのパースエラー**
    引数2（オフセット）に数値として解析できない文字列（"ABC" など）が指定された場合、値は `0` として処理され、システムは停止しません。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

### テストケース一覧

| No | テストカテゴリ | テスト条件（入力値） | 期待される結果（出力値） | 検証の目的 / 観点 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `value = "10"` | 戻り値: `10` | 10進数文字列が正しく整数値にパースされること。 |
| **2** | 正常系 | `value = "0x10"` | 戻り値: `16` | 16進数表記（0xプレフィックス）の文字列が正しく整数値にパースされること。 |

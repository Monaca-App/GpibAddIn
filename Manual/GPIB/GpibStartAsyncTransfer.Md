# コマンドリファレンス：StartAsyncTransfer

## 概要
`StartAsyncTransfer` は、Interface製ボードを使用して非同期データ転送（DMAまたはバッファリング転送）を開始する 物理層・デバイス制御系 コマンドです。
大きなデータブロックを物理的に受信する際に、受信処理の開始だけをトリガーし、呼び出し元スレッドをブロックせずに処理を並行実行させるために使用されます。実際のデータ取得は後続の `WaitAsyncTransfer` コマンドで待機・回収します。

## 💡 書式・パラメータ仕様
```csv
,SEQUENCE, [ステップキー], StartAsyncTransfer, [ボードID], [バッファサイズ], [転送ID格納変数キー]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| 引数1 | ボードID | 対象とするGPIBボードの識別ID番号。 | 固定値（整数）、PARAM変数キー、動的置換が可能です。 |
| 引数2 | バッファサイズ | 非同期受信に使用するバッファメモリサイズ（バイト数）。 | 1 以上の整数値、PARAM変数キー、動的置換が可能です。 |
| 引数3 | 転送ID格納変数キー | 払い出された非同期転送ID（整数）を格納する変数のキー名。 | `@` で始まるPARAM変数キー（例: `@TRANS_ID`）を直接指定します。 |

## 🔄 特殊置換規約・分岐規約の適用
本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。
*   **動的置換（`$`）**: 引数内で `$PARAMキー$` のように記述すると、実行時に変数プール（PARAM）の値へ動的置換されます。（適用可能な引数：引数1、引数2、引数3）
*   **ジャンプ先指定（`#`）**: 本コマンドは分岐制御を行わないため、ジャンプ先指定は適用されません。
*   **共通コマンド指定（`@`）**: 外部マクロ名や機器を対象としないため、共通コマンド指定は適用されません。
*   **カンマのエスケープ**: 引数自体にカンマを含める場合は、必ず `","` と二重引用符で囲んで記述します。

## 💡 動作例（正しい構文での記述例）
### スクリプト記述例
※COMMANDブロック配下のため、子要素行（PARAM, SEQUENCE）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。

```csv
COMMAND, "AsyncReceiveSample", ""
,PARAM, @BOARD_ID, Value, "ボード番号", "0"
,PARAM, @BUF_SIZE, Value, "バッファサイズ", "1024"
,PARAM, @TRANS_ID, Value, "転送ID", "0"
,SEQUENCE, S001, StartAsyncTransfer, $@BOARD_ID$, $@BUF_SIZE$, @TRANS_ID
```

### 実行時の挙動・変数変化
*   **実行前の状態**: `@BOARD_ID` の値は `0`、`@BUF_SIZE` の値は `1024`、`@TRANS_ID` の値は `0`。
*   **実行後の状態**: ボードID `0` でサイズ `1024` バイトの非同期転送バッファが確保されて DMA 受信が開始され、払い出された転送ID（例: `9999`）が結果格納変数 `@TRANS_ID` に格納されます。

## 🚫 エラーハンドリング・安全設計（仕様制限）
入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。
*   **非対応のドライバーがロードされている状態での呼び出し（仕様制限）**  
    本コマンドは Interface製ドライバー（`GPC4304.DLL`）専用の機能です。CONTEC製ドライバー（`CGPIB.DLL`）がロードされている動作環境で本コマンドが実行された場合、実行エンジンは「専用機能使用不可」の警告ログを出力し、物理層への通信を行わずに安全に早期正常終了（スキップ）してシステムフリーズを防ぎます。
*   **無効なバッファサイズの指定**
    引数2（バッファサイズ）に 0 以下の数値（または整数としてパースできない値）が指定された場合、エラーログを出力し、転送処理を開始せずにスキップしてシステム保護を行います。
*   **存在しない変数キーの指定**
    引数3（転送ID格納変数キー）に存在しないPARAM変数を指定した場合、エラーログを記録した上で転送IDの書き込みをスキップし、例外による強制終了を自動防御します。

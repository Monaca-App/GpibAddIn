# コマンドリファレンス：SetPhysicalLayout

## 概要
`SetPhysicalLayout` は、PCI/PCIeスロット上の物理レイアウトに応じた内部構成や信号タイミングを最適化設定する 物理層・デバイス制御系 コマンドです。
ボードの物理スロット配置やケーブル引き回し条件等に基づくハードウェア固有の最適な信号レイアウト情報を Interface 社製ドライバーに適用する目的で使用されます。

## 💡 書式・パラメータ仕様
```csv
,SEQUENCE, [ステップキー], SetPhysicalLayout, [ボードID], [レイアウトコード], [オプションフラグ]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| 引数1 | ボードID | 対象とするGPIBボードの識別ID番号。 | 固定値（整数）、PARAM変数キー、動的置換が可能です。 |
| 引数2 | レイアウトコード | 物理スロット等のレイアウトを指定するコード。 | 10進数または16進数（例: 0x01）、PARAM変数キー、動的置換が可能です。 |
| 引数3 | オプションフラグ | 設定動作を細かく修飾するオプションフラグ。 | 10進数または16進数（例: 0x00）、PARAM変数キー、動的置換が可能です. |

## 🔄 特殊置換規約・分岐規約の適用
本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。
*   **動的置換（`$`）**: 引数内で `$PARAMキー$` のように記述すると、実行時に変数プール（PARAM）の値へ動的置換されます。（適用可能な引数：引数1、引数2、引数3）
*   **ジャンプ先指定（`#`）**: 本コマンドは分岐制御を行わないため、ジャンプ先指定は適用されません。
*   **共通コマンド指定（`@`）**: 外部マクロ名や機器を対象としないため、共通コマンド指定は適用されません。
*   **カンマのエスケープ**: 引数自体にカンマを含める場合は、必ず `","` と二重引用符で囲んで記述します。

## 💡 動作例（正しい構文での記述例）
### スクリプト記述例
※COMMANDブロック配下のため、子要素行（PARAM, SEQUENCE）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。

```csv
COMMAND, "LayoutSetupSample", ""
,PARAM, @BOARD_ID, Value, "ボード番号", "0"
,PARAM, @LAY_CODE, Value, "物理レイアウト", "0x01"
,PARAM, @OPT_FLAG, Value, "オプションフラグ", "0x00"
,SEQUENCE, S001, SetPhysicalLayout, $@BOARD_ID$, $@LAY_CODE$, $@OPT_FLAG$
```

### 実行時の挙動・変数変化
*   **実行前の状態**: `@BOARD_ID` の値 is `0`、`@LAY_CODE` の値は `0x01`、`@OPT_FLAG` の値は `0x00`。
*   **実行後の状態**: ボードID `0` に対してレイアウトコード `0x01`、オプションフラグ `0x00` が物理的に設定され、ハードウェアの構成状態が変更されます。変数バッファ（PARAM）の値は変化しません。

## 🚫 エラーハンドリング・安全設計（仕様制限）
入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。
*   **非対応 of ドライバーがロードされている状態での呼び出し（仕様制限）**  
    本コマンドは Interface製ドライバー（`GPC4304.DLL`）専用の機能です。CONTEC製ドライバー（`CGPIB.DLL`）がロードされている動作環境で本コマンドが実行された場合、実行エンジンは「専用機能使用不可」の警告ログを出力し、物理層への通信を行わずに安全に早期正常終了（スキップ）してシステムフリーズを防ぎます。
*   **パラメータのパースエラー**
    引数2（レイアウトコード）や引数3（オプションフラグ）に数値として解析できない不正な文字列が指定された場合、値は `0` として処理され、強制終了を自動的に回避します。

# コマンドリファレンス：Add

## 概要
`Add` は、指定された別のコマンドマスタ（サブルーチンや外部マクロ等）が保持する変数（`PARAM`）群に対し、複数の指定キーと加算値をペア単位で動的に一括加算（インクリメント）する制御系シーケンスコマンドです。
測定チャンネルの自動インクリメント、スイープ測定時の印加電圧ステップの自動加算、リトライカウンターの更新などに使用します。

> 💡 **補足 / ⚠️ 注意**
> 単に数値を足し算するだけでなく、元の変数が持っていた文字列表記形式（整数、固定小数点、科学技術用指数表記など）を自動で解析して追従・整形するインテリジェントなフォーマット復元機能を内蔵しています。
> 例えば、元の現在値が `"1.000"`（固定小数点3桁：F3）であれば加算後も `"2.100"` となり、`"1.23E+3"`（指数表記：E）であれば `"1.2311E+03"` のように元の表記の美しさ・データ形式を破壊せずに維持・適用します。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], Add, [対象マクロ名], [変数キー1], [加算値1], [変数キー2], [加算値2]...
```

### パラメータ（引数）一覧

マクロスクリプトからは、最初の対象マクロ名に続けて、任意の個数（可変長）だけ [変数キー] と [加算値] のペアを連続して指定できます。

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 対象マクロ名 | 変数群を書き換える対象のターゲットマクロ（`COMMAND`）の名前。<br>先頭に `@` を指定すると共通コマンド（`GENERAL`）を対象とし、`@` を付けない場合は現在の機器に対するマクロを対象とします。 | 固定文字列（例: `"Sub_Measure"`、`"@Common_Measure"`）※変数置換対応 |
| **引数2** | 変数キー1 | 対象マクロ内に定義されている1つ目の変更先変数名。 | `PARAM` で定義されたキー名（例: `"CH_NO"`）※変数置換対応 |
| **引数3** | 加算値1 | 変数キー1に加算したい数値。負の数（マイナス）も指定可能。 | 固定値（例: `1` や `0.05`）またはパラメータ動的置換（例: `$P_STEP$`） |
| **引数4〜** | 可変長引数ペア | 任意の個数（可変長）だけペアを並べて一括加算可能。 | 引数2・引数3の規則に準じる |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **共通コマンド指定（`@`）**: 対象マクロ名の先頭に `@` を付与することで、自身が属する機器（デバイス）に関わらず、共通コマンド（`GENERAL`）として定義されているマクロのパラメータを対象とすることができます。`@` を付けない場合は、現在の機器に対するマクロが対象となります。（例：`"@Sub_Measure"`）
*   **動的置換（`$`）**: すべての引数において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません。
*   **カンマのエスケープ**: 可変長パラメータの各境界となるカンマと区別するため、対象マクロ名等にカンマを含む文字列を指定する場合は、必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください。

```csv
# ======================================================================
# 呼び出される側のマクロ（共通モジュール：Sub_Measure）
# ======================================================================
COMMAND, "Sub_Measure"
,PARAM, CH_NO, Value, "対象CH", "1"
,PARAM, V_SET, Value, "印加電圧", "0.000"
,SEQUENCE, 10, Send, "ROUT:CLOS (@1)"
,SEQUENCE, 20, Send, "SOUR:VOLT 2"
# ======================================================================
# 呼び出す側のメインマクロ（スイープ制御ループ）
# ======================================================================
COMMAND, "Main_Sweep_Process"
; 1. 共通マクロを呼び出して、現在のCHと電圧で計測を実行
,SEQUENCE, 10, Call, "Sub_Measure"
; 2. 【一括加算】Sub_Measure の対象CH(CH_NO)を「1」進め、印加電圧(V_SET)を「0.050V」ステップ加算
; ※元の "0.000" という表記から固定小数点3桁(F3)が自動検知され、結果は "0.050" と綺麗な桁数で維持されます
,SEQUENCE, 20, Add, "Sub_Measure", "CH_NO", "1", "V_SET", "0.05"
; 3. 必要な回数だけステップ10へ戻ってループ（条件分岐等は省略）
,SEQUENCE, 30, Jump, #10#
```

### 実行時の挙動・変数変化

*   **実行前の状態**: ターゲットとなる共通マクロ（`Sub_Measure`）の変数 `CH_NO` が `"1"`、`V_SET` が `"0.000"` の文字列状態で保持されている状態です。
*   **実行後の状態**: `Add` コマンドが実行されると、現在のマクロから指定された他のマクロ内の変数プールを直接狙って、非破壊的に数値演算が実行されます。数値のパースおよび文字列化には不変カルチャ（`CultureInfo.InvariantCulture`）が適用され、海外製計測器のデータであっても文字化けや演算誤差なく安全に処理され、変数キー `CH_NO` は `"2"`、`V_SET` は自動フォーマット復元により `"0.050"` へと同期更新されます。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。

*   **対象マクロ名（引数1）が見つからない場合**
    指定されたマクロ名がシステム内に登録されておらず、パラメータ辞書の取得に失敗した場合は、内部ログ（`LogError`）を出力して加算処理を即座に安全にアボート（処理中断）します。
*   **引数のペアが不完全（奇数個）な場合**
    [キー] に対して [値] が不足している不完全な記述がある場合、端数の不完全ペアは自動的に無視（スキップ）され、型安全を最優先して処理を継続します。
*   **辞書内キーの欠損、または非数値の検出時**
    対象マクロ内に指定された変数キーが存在しない場合、あるいは「元の現在値」や「指定された加算値」が `double.TryParse` で数値変換できない文字列であった場合は、エラーログを排出した上で該当する変数ペアの演算だけを安全にスキップし、マクロ自体のエラーを防ぎます。
*   **演算結果が不正値（NaN/Infinity）になった場合の保護**
    加算結果が計算の限界を超えて `NaN`（非数）や `Infinity`（無限大）に陥ったことを検知した場合、値の上書きによるバッファ汚染を防ぐため、値を上書きせずにログ（`LogError`）を記録して処理を安全に弾きます。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

### テストケース一覧

| No | テストカテゴリ | テスト条件（入力値） | 期待される結果（出力値） | 検証の目的 / 観点 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `currentRawVal = "1.25"`<br>`addValueStr = "0.05"` | 戻り値: `"1.30"` | 元データの小数点以下桁数（この場合はF2）を正確に自動検知して追従し、計算結果がその桁数でフォーマットされること。 |
| **2** | 正常系 | `currentRawVal = "10"`<br>`addValueStr = "1.5"` | 戻り値: `"12"` | 元データが整数（小数点なし：F0）の場合にその表記を追従すること（11.5 から四捨五入され 12 に整形されること）。 |

# GPIBマクロスクリプト 総合取扱説明書

> [!IMPORTANT]
> **基本フォーマットおよび表記言語・文字コード・AI生成仕様**  
> * **表記言語の原則（多言語化対応とデフォルト言語）**:  
>   多言語化を意識した設計とし、スクリプト内のコメント、パラメータ表示名、ダイアログメッセージ、および**シリアルステータスビット定義（`SERIALSTATUS`）の名称等の設定値文字列**は、マニュアル原本が英語等であっても、特に指定がない限り**日本語をデフォルトとして適切に翻訳して記述・設定**してください。
> * **文字コード（エンコーディング）の原則**:  
>   GPIBマクロスクリプトファイルは、**CSV形式**で保存されます。**CSVを日本語で記述する場合は、日本語Excelの制限（互換性維持および文字化け防止）から、必ず Shift-JIS (CP932) で記載・保存**してください。  
>   編集およびファイル保存時には、文字コードが Shift-JIS であることを必ず確認してください。
> * **AI生成元の明記規約（スクリプトおよびAI指示書）**:  
>   AIによってGPIBマクロスクリプト（CSV）や、**自動生成されたGPIBマクロスクリプト自動生成指示書（Markdown指示書ファイル等）**を作成・編集した場合は、トレーサビリティおよび品質管理の観点から、**「どのAIが生成したのか」が判別できる情報（AIモデル名、エージェント名、バージョン等）を必ず明記**してください。  
>   * **マクロスクリプト（CSV）**: 最先頭のヘッダコメント（最先頭行付近）に明記（例: `; 生成AI: Antigravity (Gemini 3.8 Flash)` や `; 生成AI: Claude 3.5 Sonnet` など）。  
>   * **AI指示書（Markdown）**: ファイル冒頭（タイトル直後の注記ブロック等）に明記（例: `> **生成AI**: Antigravity (Gemini 3.8 Flash)` など）。
> * **個人情報・開発環境絶対パスの完全排除規約（スクリプト、AI指示書、および全関連ドキュメント）**:  
>   AIによってGPIBマクロスクリプト（CSV）、**自動生成されるAI指示書（Markdown指示書ファイル等）**、および変更履歴まとめ等の関連ドキュメントを作成・編集する場合は、開発環境固有の絶対パス（`D:\temp\...` 等）、`file:///...` スキーム、およびユーザー名（`C:\Users\...`）を絶対に含めてはなりません。  
>   ファイル参照やMarkdownリンクを記述する場合は、必ず同一ディレクトリまたはプロジェクトからの**完全な相対パス（`./...`, `../...`）**を使用してください。パスの例示が必要な場合は、必ず汎用プレースホルダー（`<APP_DIR>`, `<MACRO_DIR>`, `C:\Macro\` 等）を使用してください。

## 📌 1. 階層構造の基本規約
解析エンジンは、行頭の文字列（第1フィールド）の状態を基準に、親ブロックとサブコマンドの親子関係を判別します。

### ⚠️ 行頭による認識ルール

* **親ブロックの開始宣言**：  
行頭にキーワード（`GENERAL` / `TITLE` / `COMMAND`）がある行。

* **サブコマンドの定義（子）**：  
行頭が「空（ホワイトスペース 或いは カンマから始まる）」で、第2フィールドにキーワードが続く行。  
直前で宣言された親ブロックに帰属します。

* **コメント行**：  
それ以外の行（親ブロックやサブコマンドに一致しない行、`;` や `#` から始まる行、完全な空行）は無視されます。

---

## 🏢 2. 親ブロックとサブコマンドの帰属関係一覧
ファイル内は大きく分けて「① 機器情報定義」と「② コマンド定義」の2つの階層構造で構成されます。

### ① 機器情報ブロック（`GENERAL` / `TITLE`）
共通機能やハードウェア（計測器）の物理構成を定義する最上階層です。

* `GENERAL`
  * `GENERAL, "GENERAL"` (共通コマンド開始) [行頭記述]
  * └── 配下サブコマンドなし (ヘッダー宣言のみ)

* `TITLE`
  * `TITLE, "[機器名称]"`    (対象機器・ハードウェア構成) [行頭記述]
  * ├── `,DEVICEBOARD`      (ボード番号指定)
  * ├── `,DEVICEADDRESS1ST` (プライマリアドレス)
  * ├── `,DEVICEADDRESS2ND` (セカンダリアドレス)
  * ├── `,DELIMITER`        (送受信終端文字)
  * ├── `,EOI`              (EOI信号線制御)
  * └── `,SERIALSTATUS`     (ステータスビット名称 ※1〜8指定)

### ② コマンド定義ブロック（`COMMAND`）
自動化マクロとして実行したい処理枠と、内部で使う変数、および具体的な実行手順を定義する階層です。

* `COMMAND`
  * `COMMAND, "[マクロ名]", "[結果格納先キー（任意）]"` [行頭記述]
  * ├── `,PARAM` (マクロ内で使用する変数・型・初期値の定義)
  * └── `,SEQUENCE` (実際に実行する処理ステップ・引数の定義)
  * ※ `[結果格納先キー]` はオプションです。マクロから出力データを返したい場合のみ指定し、出力がない場合は省略可能です。

## 📝 3. 各サブコマンドの記述仕様・パラメータ構成

### 1️⃣ TITLE ブロック帰属 サブコマンド
ハードウェア設定を規定します。すべて第2フィールドに記述します。パラメータ構成以降は無視されるため、コメントを記述することも可能です。

| サブコマンド | パラメータ構成 | 説明 |
| :--- | :--- | :--- |
| **DEVICEBOARD** | `,DEVICEBOARD, [ボード番号]` | GPIBボード（コントローラ）の番号を指定（既定値: 0）。 |
| **DEVICEADDRESS1ST** | `,DEVICEADDRESS1ST, [PAD]` | 計測器のプライマリアドレス（0〜30）を指定。 |
| **DEVICEADDRESS2ND** | `,DEVICEADDRESS2ND, [SAD]` | セカンダリアドレス（96〜127）を指定。不使用時は -1。 |
| **DELIMITER** | `,DELIMITER, [識別子]` | 送受信終端文字を指定（0:なし, 1:CRLF, 2:CR, 3:LF）。 |
| **EOI** | `,EOI, [true/false]` | 送信時のEOI信号線制御の有効・無効を指定。 |
| **SERIALSTATUS** | `,SERIALSTATUS, [番号], [名称]` | シリアルポーリング時に返るステータスビット（1〜8）の名称を定義。多言語化を意識し、英語マニュアル記載の場合でも指定がない限り日本語をデフォルトとして適切に翻訳して設定します。 |

### 2️⃣ COMMAND ブロック帰属 サブコマンド
マクロの動的データと実行フローを規定します。
すべて第2フィールドに記述します。
フィールドは可変長なので、**行末にコメントを記載できません**。

#### PARAM（変数・パラメータ定義）

| サブコマンド | パラメータ構成 | 説明 |
| :--- | :--- | :--- |
| **`PARAM`** | `,PARAM, [パラメータキー], [★データ型], [表示名], [値/選択肢...]` | コマンド内で使用する変数の型、表示名、初期値、選択肢を定義。 |

> [!CAUTION]
> **【最重要】`[表示名]` および `[値/選択肢...]` の省略・欠落厳禁（CRITICALエラー防止）**  
> `PARAM` 定義行は、解析エンジン（`GpibAnalysis.UpdateCommandProperty`）がカンマ区切りでパースする際、**最低でも第5フィールド（表示名）まで、通常は第6フィールド（初期値）までが存在することを前提**としています。  
> 
> もし `[表示名]` や `[値/選択肢...]` を省略して `,PARAM, "測定値", Range` や `,PARAM, "カウンタ", Work` のように4フィールド以下で記述した場合、システム起動時（マクロ読み込み時）に**「インデックスが配列の境界外です (IndexOutOfRangeException)」という致命的なCRITICAL例外が発生し、アプリケーションが正常起動できなくなります**。  
> 
> また、表示名を省略して値を詰めて記述（例: `,PARAM, "カウンタ", Work, "0"`）した場合、`"0"` が「表示名」として誤認され、初期値が空文字になってしまう不具合が生じます。  
> **どのようなデータ型（`Range` や `Work` を含む）であっても、必ず `[表示名]` と `[初期値]` を明記してください**（初期値が存在しない場合でも `""` を指定）。

##### 📋 各フィールドの位置と役割

| フィールド位置 | 項目名 | 必須性 | 説明・指定例 |
| :---: | :--- | :---: | :--- |
| 第1フィールド | （空白） | **必須** | 行頭カンマ（`,`）で開始（子要素を示す）。 |
| 第2フィールド | `PARAM` | **必須** | サブコマンド識別子。 |
| 第3フィールド | `[パラメータキー]` | **必須** | コマンド内で参照する変数名（例: `"測定レンジ"`, `"P_VOLT"`, `"カウンタ"`）。 |
| 第4フィールド | `[★データ型]` | **必須** | `Text`, `List`, `Range`, `Value`, `Label`, `Work` のいずれか。 |
| 第5フィールド | `[表示名]` | **必須** | UIに表示される名称。内部変数や結果格納先の場合でも省略不可（例: `"測定値"`, `"データバッファ"`, `""`）。 |
| 第6フィールド | `[初期値]` | **必須/推奨** | 変数の初期値（List型の場合は初期選択肢）。初期値が不要な場合は `""` を記述。 |
| 第7フィールド以降 | `[選択肢2, 3...]` | 任意 | List型の場合の2番目以降のドロップダウン選択肢。 |

##### ❌ 誤った記述例（NG）と ⭕ 正しい記述例（OK）

| データ型 | 判定 | 記述例 | 問題点 / 解説 |
| :--- | :---: | :--- | :--- |
| **`Range`**<br>(結果格納先) | ❌ | `,PARAM, "測定値", Range` | **【CRITICAL】** 表示名が欠落（4フィールド）。`IndexOutOfRangeException` でシステムがクラッシュします。 |
| | ⭕ | `,PARAM, "測定値", Range, "測定データ", ""` | **正常**。表示名と初期値（空文字）が正しく定義されています。 |
| **`Work`**<br>(内部変数) | ❌ | `,PARAM, "カウンタ", Work, "0"` | **【不具合】** 表示名が欠落し、`"0"` が表示名として解釈され初期値が空になります。 |
| | ⭕ | `,PARAM, "カウンタ", Work, "ループカウンタ", "0"` | **正常**。第5フィールドに表示名、第6フィールドに初期値 `"0"` が設定されます。 |
| | ⭕ | `,PARAM, "バッファ", Work, "受信バッファ", ""` | **正常**。初期値不要な場合も `""` を指定。 |
| **`List`**<br>(選択肢) | ❌ | `,PARAM, "レンジ", List, "AUTO", "0.1", "1"` | **【不具合】** `"AUTO"` が表示名になり、選択肢の割り振りがズレます。 |
| | ⭕ | `,PARAM, "レンジ", List, "測定レンジ", "AUTO", "0.1", "1"` | **正常**。第5=表示名、第6=初期選択肢、第7以降=追加選択肢。 |
| **`Value`**<br>(数値) | ❌ | `,PARAM, "上限値", Value, "100"` | **【不具合】** `"100"` が表示名になり、初期値が空になります。 |
| | ⭕ | `,PARAM, "上限値", Value, "電圧上限値", "100"` | **正常**。第5=表示名、第6=初期値。 |

💡 **PARAM サブコマンドにおける「★データ型」詳細仕様**
第4フィールド（データ型）には、エディタ上のUIおよびバリデーション形式を決定する以下のキーワードを指定します。

| 指定キーワード  |  説明・UI上の挙動 |
| :---           | :--- |
| **`Text`**    | 自由なテキスト入力を許可するスタイル。汎用文字列用。 |
| **`List`**    | ドロップダウンリスト（ComboBox）からの選択を強制・推奨するスタイル。 |
| **`Range`**   | 範囲指定用の入力スタイル。Excel上で結果セル（Result）に配列データを展開する際に、このデータ型が適用されます（カンマ・改行区切りの配列データをセルへ自動展開）。 |
| **`Value`**   | 数値入力（整合性チェック付き）を要求するスタイル。設定値や上限値用。 |
| **`Label`**   | 実行行のラベル（ジャンプ先など）を文字列指定するスタイル。 |
| **`Work`**    | ワークエリア（内部メモリや変数領域・バッファ）を指定するスタイル。※Excelアドイン側では入力セルが生成されず非表示となります。そのため、Excelからユーザーが入力・変更したいパラメータ（デバッグ疑似データなど）には使用せず、必ず `Text` や `Value` などの型を指定してください。 |

#### SEQUENCE（処理手順定義）

| サブコマンド | パラメータ構成 | 説明 |
| :--- | :--- | :--- |
| **`SEQUENCE`** | `,SEQUENCE, [ステップキー], [マクロ名], [引数1], [引数2]...` | 実際に実行する処理ステップと、渡す引数リストを定義。 |

💡 **特殊規約**
* **共通コマンド指定**:  
  外部マクロ（サブルーチン）を参照・操作するコマンド（`Call`, `ParamSet`, `ParamGet`, `Add`, `Mul`, `Div`）において、ターゲットとなるマクロ名の先頭に `@` を付与することで共通コマンド（`GENERAL`）として登録されたマクロを対象とします。`@` を付けない場合は、現在の機器に対するマクロが対象となります。
* **動的置換**:  
  引数内で `$PARAMキー$` のようにパラメータキーの両端を `$` で囲むと、実行時に PARAM の値へと動的置換されます。
* **条件ジャンプ**:  
  ジャンプ先を指定する場合は、ターゲットとなるラベル名（ステップキー）を `#10#` や `#Start#` のように `#` で囲んで引数に指定します（ラベル名には任意の文字列または数値が使用可能です）。
* **カンマのエスケープ**:  
  引数自体にカンマを含める場合は、必ず `","` のように二重引用符で囲んで記述します。
* **デバッグデータ設定と受信フローの順序（最重要・AI指示書必須制約）**:  
  デバッグ実行モード（`DebugDLL=true`）において、`Receive` コマンドは内部バッファ（`GpibDLL.DebugReceiveData`）から疑似受信データを取得します。そのため、疑似受信データを設定する **`DebugData` コマンドは、必ず `Receive` コマンドの直前（前）に配置しなければなりません**。`Receive` より後に配置しても、受信処理には反映されません。  
  データ測定・回収を行うマクロシーケンスでは、必ず以下の順序でステップを構成してください：  
  1. `[クエリ送信]`（`Send` または `Call, "送信", ...`）  
  2. **`DebugData, [疑似データ]`** （デバッグ用受信データを事前設定）  
  3. **`Receive`** （物理受信または疑似データ取得）  
  4. **`WaitData`** （受信完了待機・タイムアウト判定）  
  5. **`SetData`** （受信データの抽出・パラメータ格納）
* **デバッグ疑似データのデータ型規約（Excel連携・Work以外での定義鉄則）**:  
  デバッグ疑似データを格納するパラメータ（`DEBUG_VAL` や `デバッグデータ` 等）は、**Excel シート上からユーザーが任意にテストデータを指定・変更できるよう、`Work` 型ではなく必ず `Work` 以外の型（`Text` 型推奨、または `Value` 型）として定義してください**。  
  ※`Work` 型で定義されたパラメータは Excel アドイン側でパラメータ入力セルが生成されず、Excel からのテストデータ入力・変更ができなくなります。
* **タイムスタンプ有効時のデータパース・3列展開カンマ分離規約（最重要・AI指示書必須制約）**:  
  タイムスタンプ機能が有効化（`TimeStamp, true`）されている場合、システムは受信データを以下の形式で取得します：  
  `[ 2026/10/31 23:59:59.999 ] R:data`  
  （※角括弧 `[...]` 内に日付と時刻・ミリ秒、続いて受信識別子 `R:`、および機器からの応答データ本体）  
  この受信データを `SetData` または `SetData_RowAdd` 等で処理する場合、**日付・時刻・測定データをカンマで分離し、Excel上で3列展開されるフォーマット（`"%s, %s, %f"` 形式）として扱うことを標準規約とします**。  
  これによって、Excel上で結果格納先パラメータ（`Range` 型推奨）へ展開される際、**1列目に日付、2列目に時刻、3列目に測定値**が自動的に3列の2次元表として綺麗に展開・整列されます。  
  * **パース指定の標準パターン例 (`SetData_RowAdd`)**:  
    ```csv
    ; 日付・時刻・測定数値を分離し、カンマ区切り（3列マトリクス）として行追記格納
    ,SEQUENCE, 80, SetData_RowAdd, "測定値", "[ %s %s ] R:%f", "%s, %s, %0.6f"
    ```
    ※受信データ内の `[ 日付 時刻 ] R:数値` から、`%s %s` で日付と時刻を別々に抽出し、`%f` で数値を抽出した上で、sprintf 書式 `"%s, %s, %0.6f"` によって `日付, 時刻, 数値` のカンマ区切りテキスト（3列展開）として結合・蓄積します。  
    ※文字列データとしてそのまま抽出・結合する場合は、`SetData_RowAdd, "測定値", "[ %s %s ] R:%s", "%s, %s, %s"` のように指定します。
* **タイムスタンプ無効時（通常時）のパース指定規約**:  
  タイムスタンプが無効（`TimeStamp, false`）の場合であっても、受信バッファは測定値のみ格納されるのではなく、受信マークを含む **`R:data` 形式（例: `R:12.345`）** で取得されます。したがって、`SetData` または `SetData_RowAdd` による数値パース書式には `"%f"` ではなく **`"R:%f"` 形式** を指定する必要があります（例: `,SEQUENCE, 80, SetData_RowAdd, "測定値", "R:%f", "%0.6f"`）。
* **TimeStamp コマンドの実行順序鉄則（すべての送受信コマンドに先立って実行・最重要規約）**:  
  `TimeStamp` コマンド（`TimeStamp, true` または `TimeStamp, $パラメータ$`）は、**`Send` や `Receive` を含むすべての送受信コマンドに先立って（最優先で）実行しなければなりません**。送受信が一度でも行われた後に `TimeStamp` を設定すると、通信バッファやログの整合性に問題が生じる恐れがあるため、シーケンスの先頭（ステップ10等）で必ず送受信コマンドより前に実行してください。
* **コマンド終了時の TimeStamp OFF 復帰鉄則（他コマンドへの影響防止・AI指示書必須制約）**:  
  `TimeStamp` コマンドによるタイムスタンプ機能の変更は、システム全体の受信データ取得状態に影響を与えます。そのため、タイムスタンプ機能を使用したコマンドを定義した場合、**他のコマンドや後続シーケンスへの予期せぬ影響を確実に防止するため、そのコマンドの終了時（`Exit` 直前）に必ず `TimeStamp, false` を実行して機能を OFF に戻さなければなりません**。
* **測定マクロ設計の標準規約（単発・連続の統合と即時終了規約）**:  
  測定マクロは、単発専用マクロ（`_Single`）と連続専用マクロ（`_Continuous`）に分離・重複作成せず、**「回数指定可能な連続ループ構造」を基本骨格として定義し、単発測定は「取得回数＝1」で兼ねることを標準原則とします**。  
  * **初期値の統一**: `取得回数` パラメータの初期値は必ず `"1"` と設定し、デフォルト実行で単発測定として動作させます。  
  * **単発測定時（回数＝1）の即時終了規約**:  
    データ回収・格納後にカウンタをインクリメントし、規定回数到達判定を行います。規定回数（1回など）に達した場合は、**`Wait`（サンプリング周期待機）をスキップして即座に終了処理（`Exit`）へジャンプ**させてください。これにより、単発実行時にサンプリング待ち時間が発生せず、最速で測定が完了します。
* **初期化（INIT）の独立化と測定コマンドの繰り返し実行規約**:  
  自動計測やExcel上から測定コマンドを高速かつ柔軟に繰り返し呼び出せるようにするため、通信ボードの接続・初期化（`Open`, `Init`, 機器リセットコマンド等）は各測定コマンド内には含めず、**独立した初期化コマンド（`INIT`）として分離定義することを標準原則とします**。  
  * **測定コマンドの軽量化**: 各測定コマンド内では毎回 `Open` / `Close` を行わず、すでに初期化済みのセッション上で「機器設定 ➔ トリガ ➔ 受信 ➔ 格納 ➔ 回数判定 ➔ Exit」のみを実行します。  
  * **メリット**: 測定コマンドをループ等で何度繰り返し実行しても、都度ボードの再接続や切断によるオーバーヘッドが発生せず、機器の設定状態を維持したまま最小遅延で高速な測定を継続できます。
  * **終了処理の分離**: 計測作業全体の終了時に通信ボードを安全に解放するため、独立した終了コマンド（`CLOSE`）を設けます。

## 📊 4. GPIB ドライバー機能比較（CONTEC vs Interface）

### 4.4 ドライバー間における動作・パラメータ仕様の詳細差異

両ドライバーのAPIマッピングおよび実装方式の違いにより、以下の挙動・パラメータ仕様の違いが存在します。

#### 1. タイムアウト設定 (`SetTimeOut` / `GetTimeOut`)
* **CGPIB (CONTEC)**: ミリ秒単位の設定値をそのままドライバーに適用します。
* **GPC4304 (Interface)**: タイムアウト設定時に指定されたミリ秒値を内部で `100` で割った値（100msステップ、最小値は `1`）としてドライバーへ登録します。値を取得する際は、ドライバーから取得したステップ数に `100` を乗算したミリ秒値に復元します。そのため、設定したタイムアウト値は100ms単位に丸められます。

#### 2. デリミタ設定 (`SetDelim` / `GetDelim`)
* **CGPIB (CONTEC)**: デリミタの数値コードおよびEOI/EOS状態をそのまま数値として適用します。
* **GPC4304 (Interface)**: デリミタは `/SDELIM=[文字列]` / `/RDELIM=[文字列]` コマンドを使用して、内部で文字列表現（`"CRLF"`, `"CR"`, `"LF"`, `"EOI"`）にマッピングされ設定されます。また、取得の際も取得された数値に基づいてマクロ用コードに逆変換されます。

#### 3. スレーブ動作・モード設定 (`MODE` および `GpibSetStatus` の 0x0A)
* **CGPIB (CONTEC)**: 共通のステータス設定を通じてモード値が適用されます。
* **GPC4304 (Interface)**: スレーブモード/マスタモードの切り替えには専用API `PciGpibExReSysCtrl` を使用します。また、スレーブモードにおけるシリアルポーリング確認 (`GpibCheckSPoll`) では、`PciGpibExSlavCheckStb` のステータス値を利用した同期処理が行われます。

#### 4. パラレルポーリング構成設定 (`PPLSet`) の制限
* **CGPIB (CONTEC)**: 指定されたアドレスリスト、データラインリスト、極性リストに基づいて詳細なパラレルポーリングを構成します。
* **GPC4304 (Interface)**: 内部で `PciGpibExCfgPpoll` を呼び出しますが、極性およびデータラインの設定として `0x09` 固定値が適用される簡易実装となっています。そのため、マクロ引数で指定された「データラインリスト」および「極性リスト」のパラメータは実質的に無視されます。

#### 5. エスケープキー監視 (`SetEscape` / `GetEscape`)
* **CGPIB (CONTEC)**: ドライバーレベルでのエスケープキー監視に対応しています。
* **GPC4304 (Interface)**: 非サポートのため、マクロで本コマンドを実行しても物理的な動作は行われず、常に成功（`0` を返すダミー動作）として処理されます。

#### 6. スムーズモード設定 (`Smooth`)
* **CGPIB (CONTEC)**: ノイズ対策用としてスムーズモードを設定します。
* **GPC4304 (Interface)**: 非サポートです（Interface社製ハードウェアではデータ転送ウェイトが自動最適化されるため設定不要）。マクロから呼び出された場合は、エラーや例外をスローせず安全に無視（スキップ）して正常終了します。

## 🚀 5. マクロコマンド詳細リファレンス

### 5.1 配列バッファ操作系

* [**Array_Init**](./Array/GpibArray_Init.Md)
  * **概要** :  
   指定されたX軸/Y軸の要素数とデリミタに基づいて、Work型変数向け二次元配列バッファを初期化生成。要素数が0以下は早期リターン。
  * **書式**:  
   `,SEQUENCE, [ステップキー], Array_Init, [格納先変数], [X軸要素数], [Y軸要素数], [区切り文字]`
  * **指定例**:  
   `,SEQUENCE, 10, Array_Init, CH1_RAW, 3, 5, ","`（カンマを指定する場合は必ず `","` で囲む）

* [**Array_Set**](./Array/GpibArray_Set.Md)
  * **概要** :  
   二次元配列バッファの特定のインデックス（X, Y）に値を上書き。配列長を超えている場合は自動拡張。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Array_Set, [対象変数], [X軸インデックス], [Y軸インデックス], [区切り文字], [設定値]`
  * **指定例**:  
   `,SEQUENCE, 20, Array_Set, CH1_GRID, 3, 0, ",", "12.34"`

* [**Array_Split**](./Array/GpibArray_Split.Md)
  * **概要** :  
   二次元配列から指定された矩形範囲を切り出し、別の変数へ格納。はみ出した領域は空文字で自動補完。
  * **書式** :

  * **指定例**:  
   `,SEQUENCE, 30, Array_Split, CH1_ONLY, BIG_DATA, "0-1", "0-50", ","`

### 5.2 外部マクロ・変数制御系

* [**Call**](./Param/GpibCall.Md)
  * **概要** :  
   指定された外部マクロに対して可変長のパラメータを動的に一括代入し同期実行（マクロ名の先頭に `@` を付与することで共通コマンド指定が可能。指定しない場合は現在の機器に対するマクロが対象）。UIフリーズを防止。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Call, [呼び出し先マクロ名], [[引数キー1], [値1], [引数キー2], [値2] ...]`
  * **指定例**:  
   `,SEQUENCE, 10, Call, "Sub_Measure", "1", "$1$", "2", "5.5"`
   `,SEQUENCE, 20, Call, "@Common_Measure", "1", "$1$"`

* [**ParamSet**](./Param/GpibParamSet.Md)
  * **概要** :  
   別のマクロが保持する内部パラメータ群に対し、複数の指定キーと設定値をペア単位で動的に一括代入（マクロ名の先頭に `@` を付与することで共通コマンド指定が可能。指定しない場合は現在の機器に対するマクロが対象）。
  * **書式** :  
   `,SEQUENCE, [ステップキー], ParamSet, [対象マクロ名], [設定する値1], [対象変数キー1], [[設定する値2], [対象変数キー2] ...]`
  * **指定例**:  
   `,SEQUENCE, 15, ParamSet, "Sub_Measure", "10V", "RANGE", "5", "TIMEOUT"`
   `,SEQUENCE, 16, ParamSet, "@Common_Measure", "10V", "RANGE"`

* [**ParamGet**](./Param/GpibParamGet.Md)
  * **概要** :  
   別マクロの内部パラメータ群から複数の指定キーの値を動的に一括取得し、自マクロの変数プールへ書き戻す（マクロ名の先頭に `@` を付与することで共通コマンド指定が可能。指定しない場合は現在の機器に対するマクロが対象）。
  * **書式** :  
   `,SEQUENCE, [ステップキー], ParamGet, [参照元マクロ名], [自格納先変数1], [相手参照先変数1], [[自格納先変数2], [相手参照先変数2] ...]`
  * **指定例**:  
   `,SEQUENCE, 20, ParamGet, "Sub_Measure", "1", "RAW_DATA", "2", "ERR_CODE"`
   `,SEQUENCE, 21, ParamGet, "@Common_Measure", "1", "RAW_DATA"`

* [**Add**](./Param/GpibParamAdd.Md) / [**Mul**](./Param/GpibParamMul.Md) / [**Div**](./Param/GpibParamDiv.Md)
  * **概要** :  
   別マクロのパラメータに対して一括演算を実行（マクロ名の先頭に `@` を付与することで共通コマンド指定が可能。指定しない場合は現在の機器に対するマクロが対象）。元の表記形式（整数・科学表記など）を自動解析してフォーマット復元。Divは0除算防御付き。
  * **書式** :  
   `,SEQUENCE, [ステップキー], [Add/Mul/Div], [対象マクロ名], [変数キー1], [演算値1]...`
  * **指定例**:  
   `,SEQUENCE, 25, Add, "Sub_Measure", "1", "1", "2", "0.05"`
   `,SEQUENCE, 26, Add, "@Common_Measure", "1", "1"`

### 5.4 物理通信・ライン制御系

* [**Open**](./GPIB/GpibOpen.Md) / [**Close**](./GPIB/GpibClose.Md)
  * **概要** :  
   GPIB物理層の回線接続および切断を制御。Open時はIFC/REN/DCLを一斉送出してバスをクリーン化。Closeはfinallyガード付き。
  * **書式** :  
   `,SEQUENCE, [ステップキー], [Open/Close]`

* [**Init**](./GPIB/GpibInit.Md)
  * **概要** :  
   対象機器のオブジェクト情報を通信DLLへ登録し、構成ファイルから読み込まれたデリミタ設定をハードウェア層へ同期適用。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Init`

* [**Send**](./GPIB/GpibSend.Md) / [**Receive**](./GPIB/GpibReceive.Md)
  * **概要** :  
   機器へのコマンド送信、および物理受信を制御。物理層エラーやバス固着に対する自動リカバリ（最大3回リトライ）を内包。※同期的なポーリング受信で使用。**Receive 結果をシーケンスパラメータに反映するには、WaitData を用います。**  
   ⚠️ **デバッグ実行時の重要制約（AI必須）**: デバッグ環境（`DebugDLL=true`）では、`Receive` 実行時に `GpibDLL.DebugReceiveData` に保持されている疑似データを受信バッファへ読み出します。したがって、**デバッグ用の疑似受信データを適用する場合は、必ず `Receive` の直前（前）に `DebugData` コマンドを実行してデータをセットしておく必要があります。**
  * **書式** :  
   `,SEQUENCE, [ステップキー], [Send/Receive], [送信文字列(Sendのみ)]`
  * **指定例**:  
   `,SEQUENCE, 10, Send, "*IDN?"`

* [**SendDirect**](./GPIB/GpibSendDirect.Md) / [**ReceiveDirect**](./GPIB/GpibReceiveDirect.Md)
  * **概要** :  
   イクウィップメント（機器）の事前登録を行わず、ボード番号と宛先アドレスリストを直接指定して、データ（バイナリ）を直接送信および受信します。
  * **書式** :  
   `,SEQUENCE, [ステップキー], SendDirect, [ボード番号], [宛先アドレスリスト(カンマ区切り)], [送信データ]`  
   `,SEQUENCE, [ステップキー], ReceiveDirect, [ボード番号], [受信元アドレスリスト(カンマ区切り)], [格納先パラメータ名]`
  * **指定例**:  
   `,SEQUENCE, 15, SendDirect, 0, "1,2", "*RST"`  
   `,SEQUENCE, 16, ReceiveDirect, 0, "1", RESULT_VAL`

* [**IFC**](./GPIB/GpibIFC.Md) / [**DCL**](./GPIB/GpibDCL.Md) / [**SDC**](./GPIB/GpibSDC.Md)
  * **概要** :  
   バス全体のリセット（IFC/DCL）および特定機器のピンポイントリセット（SDC）を物理送出。
  * **書式** :  
   `,SEQUENCE, [ステップキー], [IFC/DCL/SDC]`

* [**Reset**](./GPIB/GpibReset.Md)
  * **概要** :  
   指定されたボードIDまたは機器IDに対して物理的にリセット（再初期化）を行います。PCのスリープ復帰後のリカバリ等に有効です。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Reset, [対象のボードID/機器ID]`
  * **指定例**:  
   `,SEQUENCE, 22, Reset, 0`

* [**SPL**](./GPIB/GpibSPL.Md) / [**SSR**](./GPIB/GpibSSR.Md) / [**SSR_CLR**](./GPIB/GpibSSR_CLR.Md)
  * **概要** :

* [**PPL**](./GPIB/GpibPPL.Md) / [**PPLSet**](./GPIB/GpibPPLSet.Md) / [**PPLReset**](./GPIB/GpibPPLReset.Md) / [**IST**](./GPIB/GpibIST.Md)
  * **概要** :

  * **概要** :

  * **書式** :  
   `,SEQUENCE, [ステップキー], GET, [測定周期(ms)], [計測回数]`

* [**Find**](./GPIB/GpibFind.Md) / [**Smooth**](./GPIB/GpibSmooth.Md) / [**SRQSend**](./GPIB/GpibSRQSend.Md)
  * **概要** :  
   アクティブなリスナ機器の自動探索（Find）、スムーズモードの有効設定（Smooth）、および自ボードからのSRQアサート制御（SRQSend）を制御。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Find, [ボード番号], [開始プライマリアドレス], [開始セカンダリアドレス], [格納先変数]`  
   `,SEQUENCE, [ステップキー], Smooth, [ボード番号], [有効フラグ(1/0)]`

  * **指定例**:  
   `,SEQUENCE, 45, Find, 0, 0, 0, FOUND_ADDRS`  
   `,SEQUENCE, 46, Smooth, 0, 1`  
   `,SEQUENCE, 47, SRQSend, 0, 1, 0x40`

> 💡 **GPIBデータ受信方式の選択（ポーリングと割り込み）**
> システム構成や測定器の仕様に応じて、GPIBからのデータ受信は以下の2つのアプローチから選択できます。
> * **同期ポーリング方式 (`Receive` コマンド)**:
>   `Send` コマンド等で測定命令を送信した後、同期的に `Receive` コマンドを実行してデータを物理受信する方式です。シンプルで最も一般的な制御フローです。
> * **非同期割り込み方式 (`GET` コマンド)**:
>   `GET` コマンドでグループ実行トリガーを送信した後、測定器の測定完了イベント（SRQ）を Windows メッセージループ（`WndProc`）にて非同期に検知し、自動的に `Receive`（データ受信）を実行するイベント駆動型の受信方式です。複数機器の同期測定や、メインUIをフリーズさせずにバックグラウンドで連続測定を行いたい場合に適しています。

### 5.5 データ解析・ファイルI/O・UI対話系

* [**Wait**](./Work/GpibWait.Md)
  * **概要** :  
   指定されたミリ秒時間だけ、シーケンスの進行を一時停止します。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Wait, [待機時間(ms)]`
  * **指定例**:  
   `,SEQUENCE, 20, Wait, 1000`

* [**WaitData**](./Work/GpibWaitData.Md)
  * **概要** :  
   GPIB機器からのデータ受信を一定時間ポーリング監視します。タイムアウト発生時は指定されたジャンプ先ラベル名へ条件ジャンプします。**Receive 結果をシーケンスパラメータに反映する際にも本コマンドを用います。**
  * **書式**:  
   `,SEQUENCE, [ステップキー], WaitData, [タイムアウト時のジャンプ先ラベル名(任意)]`
  * **指定例**:  
   `,SEQUENCE, 20, WaitData, #10#` （または `#Retry#`）

* [**SetData**](./Work/GpibSetData.Md) / [**SetData_RowAdd**](./Work/GpibSetDataRowAdd.Md)
  * **概要** :  
   受信データに対し sscanf 抽出および可変長 sprintf 書式化チェーンを適用して変数へ格納。RowAddは末尾に改行付きで追記。  
   ※受信データはタイムスタンプ無効時でも測定値のみではなく `"R:data"` 形式となるため、通常は `"R:%f"` 形式で指定します。タイムスタンプが有効（`TimeStamp, true`）な場合は `"[ yyyy/MM/dd HH:mm:ss.fff ] R:data"` 形式となり、Excel上で日付・時刻・数値の3列展開を行うため `"[ %s %s ] R:%f", "%s, %s, %0.6f"` のように書式指定します。
  * **書式** :  
   `,SEQUENCE, [ステップキー], [SetData/SetData_RowAdd], [格納先変数], [sscanf書式], [sprintf書式1]...`
  * **指定例**:  
   `; タイムスタンプ無効時（R:%f 形式での抽出例）`  
   `,SEQUENCE, 20, SetData_RowAdd, "測定値", "R:%f", "%0.2f"`  
   `; タイムスタンプ有効時（日付・時刻・数値をカンマ区切りの3列展開で格納する例）`  
   `,SEQUENCE, 30, SetData_RowAdd, "測定値", "[ %s %s ] R:%f", "%s, %s, %0.6f"`

* [**SkipData**](./Work/GpibSkipData.Md)  / [**SkipLine**](./Work/GpibSkipLine.Md)
  * **概要** :  
   不要なデータを sscanf 書式で読み飛ばすか（SkipData）、不要な応答ヘッダー等を指定行数分だけ一括読み飛ばし（SkipLine）を実行。
  * **書式** :  
   `,SEQUENCE, [ステップキー], [SkipData/SkipLine], [書式またはスキップ行数]`

* [**LogOut**](./Work/GpibLogStream.Md)
  * **概要** :  
   指定されたフォーマットと可変長引数を用いて、コマンドシーケンスの実行ログを指定のテキストファイルに追記します。
  * **書式** :  
   `,SEQUENCE, [ステップキー], LogOut, [ファイルパス], [追加書き込みフラグ(任意: true/false)]`
  * **指定例**:  
   `; 新規書き込みでログファイルを開く例`  
   `,SEQUENCE, 10, LogOut, "C:\\Log\\data.txt", false`  
   `; ログファイルを閉じる例（引数なし）`  
   `,SEQUENCE, 90, LogOut`

* [**WriteFile**](./Work/GpibWriteFile.Md)
  * **概要** :  
   指定されたデータブロック（TextBlock）を、指定された排他モード（新規上書き/追記）でテキストファイルに書き込みます。
  * **書式** :  
   `,SEQUENCE, [ステップキー], WriteFile, [ファイルパス], [書き込みデータ], [モード( New/Add )]`
  * **指定例**:  
   `; 変数 $MyVal$ の内容をファイルに追記（Add）する例`  
   `,SEQUENCE, 30, WriteFile, "C:\\Log\\data.txt", "$MyVal$", "Add"`

* [**SendFile**](./Work/GpibSendFile.Md)
  * **概要** :  
   外部テキストファイル形式のマクロコマンドを、現在のコマンドシーケンス内に非同期的に挿入し、実行します。
  * **書式** :  
   `,SEQUENCE, [ステップキー], SendFile, [ファイルパス]`
  * **指定例**:  
   `; 外部ファイル「C:\\Macro\\test.mac」の内容をこの位置に展開して実行`  
   `,SEQUENCE, 50, SendFile, "C:\\Macro\\test.mac"`

* [**MODE**](./Work/GpibMODE.Md)  
  * **概要** :  
   現在の通信対象デバイスのリモートステータス（Local / Remote など）を取得し、指定パラメータに格納します。  
  * **書式** :  
   `,SEQUENCE, [ステップキー], MODE, [結果格納先変数キー]`
  * **指定例**:  
   `,SEQUENCE, 20, MODE, MyStatus`

* [**TimeStamp**](./Work/GpibTimeStamp.Md)
  * **概要** :  
   タイムスタンプ機能のON/OFFを制御する引数が必要です（"0" または "false" で無効、それ以外で有効）。  
   有効化時は、受信データが `[ yyyy/MM/dd HH:mm:ss.fff ] R:data` 形式で取得されます。`SetData` / `SetData_RowAdd` で処理する場合は、タイムスタンプとデータを分離し、各々をカンマ区切りデータとして扱ってください。  
   ※**【最重要】すべての送受信コマンド（`Send` / `Receive`）に先立って実行してください**。送受信後に設定すると通信バッファやログの整合性に影響を与える恐れがあります。また、他コマンドへの影響を防ぐため、本機能を使用したコマンドの終了時（`Exit` 直前）には必ず `TimeStamp, false` を実行して機能を OFF に戻してください。
  * **書式** :  
   `,SEQUENCE, [ステップキー], TimeStamp, [ON/OFF]`
  * **指定例**:  
   `; タイムスタンプ機能を有効化する例（必ず送受信コマンドより前に実行）`  
   `,SEQUENCE, 10, TimeStamp, true`  
   `,SEQUENCE, 20, Send, "*IDN?"`  
   `; コマンド終了時にタイムスタンプ機能を無効化（OFF復帰）する例`  
   `,SEQUENCE, 90, TimeStamp, false`  
   `,SEQUENCE, 95, Exit`

* [**MsgBox**](./Work/GpibMsgBox.Md)
  * **概要** :  
   スレッド安全な最前面ポップアップ対話（MsgBox）を制御。
  * **書式** :  
   `,SEQUENCE, [ステップキー], MsgBox, [メッセージ], [タイトル(任意)], [ボタン構成(任意)], [デフォルトボタン(任意)], [結果格納先変数(任意)]`
  * **指定例**:  
   `; はい/いいえ を選択させ、結果を結果格納用変数 $Ans$ に保存する例`  
   `,SEQUENCE, 100, MsgBox, "実行しますか？", "確認", "YesNo", "Button1", Ans`

* [**Replace**](./Work/GpibReplace.Md)
  * **概要** :  
   指定された変数内の文字列に対し、正規表現パターンによる一括置換処理を実行。指定キーが存在しない場合も早期リターン。
  * **書式** :  
   `,SEQUENCE, [ステップキー], Replace, [置換対象 of テキスト], [検索正規表現パターン], [置換後の文字列]`
  * **指定例**:  
   ; アルファベット of 文字群を一括除去して純数値のみにする記述例  
    `,SEQUENCE, 40, Replace, $SrcData$, "[A-Za-z]", ""`

* [**DebugData**](./Work/GpibDebugData.Md)
  * **概要** :  
   デバッグ実行時（DLL無し時）の疑似受信応答データ（`GpibDLL.DebugReceiveData`）を動的に設定・更新。  
   ⚠️ **【配置位置の絶対制約（AI指示書必須ルール）】**:  
   本コマンドは、以降に実行される `Receive` コマンドが読み出す内部バッファに疑似データを事前設定するものです。そのため、**必ず `Receive` コマンドの直前（前）に配置してください**。`Receive` の後や `SetData` の後に配置しても受信処理には一切反映されません。
  * **書式** :  
   `,SEQUENCE, [ステップキー], DebugData, [疑似受信データ]`
  * **データ回収の標準手順**:  
   `クエリ送信` ➔ **`DebugData`** ➔ **`Receive`** ➔ `WaitData` ➔ `SetData`
  * **指定例**:  
   `; 測定クエリ送信後、Receive 直前にデバッグデータをセットする例`  
   `,SEQUENCE, 40, Call, "送信", "送信データ", "FUNC $ファンクション$, $レンジ$, $WORK$"`  
   `,SEQUENCE, 45, DebugData, "$デバッグデータ$"`  
   `,SEQUENCE, 50, Receive`  
   `,SEQUENCE, 55, WaitData, #70#`  
   `,SEQUENCE, 60, SetData, "受信データ", "R:%f", "%0.6f"`

#### 📊 サポートする sscanf書式（％演算子）

| 指定子 | 説明 | 変換・置換の挙動 |
|---|---|---|
| %d | 10進数整数 | 符号や数値をパースし、整数文字列として結果に反映 |
| %f / %u | 浮動小数点数 / 実数 | 小数点や指数をパースし、実数文字列として結果に反映 |
| %x | 16進数整数 | 16進数を抽出し、10進数整数文字列へインライン変換して反映 |
| %y | 16進数IEEE 754単精度実数 | 16進数を抽出し、10進数実数文字列へダイレクト変換して反映 |
| %s | 任意文字列 | 空白、カンマ、セミコロン、改行等に達するまでの文字を抽出して反映 |
| %z | データ破棄（スキップ） | 次の区切り文字に達するまでデータを読み進めるが、結果からは除外（消滅） |

> 💡 **sscanf における定数リテラル（固定文字列）の読み飛ばし規約**  
> 書式文字列内に記述された定数リテラル（受信識別マーク `"R:"` やヘッダー `"DATA:"`、記号 `"["`、`"]"` など）は、受信データとの**照合（同期）および読み飛ばし（スキップ）用**として機能し、**抽出結果には含まれません**。  
> これにより、例えば `"R:12.345"` に対して `"R:%f"` を指定した場合、受信マーク `"R:"` が自動的に除外されて数値 `"12.345"` のみが抽出されます。  
> また、書式文字列内の空白文字は結果に維持されるため、`"[ %s %s ] R:%f"` のように指定することで日付・時刻・測定数値を安全に抽出できます（抽出後の sprintf 書式で `"%s, %s, %f"` とカンマ結合することでExcelの3列展開を実現します）。

#### 📊 サポートする sprintf書式（％演算子）

| 指定子 [1, 2] | 説明 | 書式化・置換の挙動 |
|---|---|---|
| %d | 10進数整数 | 指定の幅（Width）に合わせて右詰めまたは左詰めで配置 |
| %f / %u | 浮動小数点数 / 実数 | 指定された小数点以下精度（Precision）で四捨五入して配置 |
| %x | 16進数整数 | 10進数数値を16進数大文字文字列へ変換して配置 |
| %g | 浮動小数点ビット変換 | 単精度浮動小数点（float）の内部ビットパターンをそのまま16進数化 |
| %s | 任意文字列 | 切り出した文字列をそのまま配置。最大文字数の制限にも対応 |
| %z | データ破棄（スキップ） | 対応する引数データを1つパース消費するが、結果文字列からは除外（消滅） |

## 💡 6. 記述サンプル
親ブロックが左端から始まり、帰属するサブコマンドがホワイトスペース（あるいはカンマ）によって1段下がってパースされる構造に注目してください。

```csv
; ==========================================
; 機器情報定義ブロック（HP 3458A 用物理設定）
; ==========================================
TITLE, "HP_3458A"
,DEVICEBOARD, 0           ; GPIBボード番号を指定（既定値: 0）
,DEVICEADDRESS1ST, 22     ; HP 3458Aのデフォルトアドレス（22）を指定
,DEVICEADDRESS2ND, -1     ; セカンダリアドレスは不使用（-1）
,DELIMITER, 1             ; 送受信終端文字（デリミタ）に「CRLF(1)」を指定
,EOI, true                ; 送信時のEOI信号線制御を「有効」に設定

; ==========================================
; コマンド定義ブロック 1: 初期化マクロ (INIT)
; 計測開始前に1回実行し、以降の測定コマンドの高速・連続な繰り返し実行を可能にする
; ==========================================
COMMAND, "INIT"
,SEQUENCE, 10, Open
,SEQUENCE, 20, Init
,SEQUENCE, 30, Send, "END ALWAYS"
,SEQUENCE, 40, Exit

; ==========================================
; コマンド定義ブロック 2: DC電圧測定マクロ (Measure_DCV)
; 初期化済みセッション上で動作し、何度でも繰り返し高速に実行可能
; 単発測定は「取得回数=1」で兼用し、規定回数到達時は即座に終了
; ==========================================
COMMAND, "Measure_DCV", "V_DATA"
; ------------------------------------------
; 変数・パラメータ定義 (PARAM)
; ※表示名（第5フィールド）および初期値（第6フィールド）は必須
; ------------------------------------------
,PARAM, P_RANGE, List, "測定レンジ", "AUTO", "0.1", "1", "10", "100", "1000"
,PARAM, P_COUNT, List, "取得回数", "1", "5", "10", "20", "50", "100"
,PARAM, P_INTERVAL, List, "サンプリング周期(ms)", "100", "200", "500", "1000"
,PARAM, P_TIMESTAMP, List, "タイムスタンプ", "false", "true"
; V_DATA: 取得した測定データを保存するExcelセル展開用領域（初期値: 空文字必須）
,PARAM, V_DATA, Range, "測定データ結果", ""
; 内部ループ制御変数（Work型）
,PARAM, LOOP_CNT, Work, "ループカウンタ", "0"
; デバッグ疑似データ（Excelから指定できるようText型で定義）
,PARAM, DEBUG_VAL, Text, "デバッグ疑似データ", "10.000000"
; ------------------------------------------
; 処理手順定義 (SEQUENCE)
; ※毎回Open/Init/Closeを行わず、設定・測定・格納のみを高速実行
; ※TimeStampはすべての送受信コマンドに先立って最優先で実行
; ------------------------------------------
,SEQUENCE, 10, TimeStamp, $P_TIMESTAMP$
,SEQUENCE, 20, Send, "FUNC DCV, $P_RANGE$"
,SEQUENCE, 30, ParamSet, "Measure_DCV", "0", "LOOP_CNT"
; --- 測定ループ先頭 ---
,SEQUENCE, #LOOP_START#, Send, "TRIG SGL"
,SEQUENCE, 50, DebugData, "$DEBUG_VAL$"
,SEQUENCE, 60, Receive
,SEQUENCE, 70, WaitData, #TIMEOUT#
; --- タイムスタンプ有無のパース分岐 ---
,SEQUENCE, 80, Equ, "$P_TIMESTAMP$", "true", #PARSE_NO_TS#
,SEQUENCE, 90, SetData_RowAdd, "V_DATA", "[ %s %s ] R:%f", "%s, %s, %0.8f"
,SEQUENCE, 100, Jump, #CHECK_COUNT#
,SEQUENCE, #PARSE_NO_TS#, SetData_RowAdd, "V_DATA", "R:%f", "%0.8f"
; --- 回数判定（規定回数到達時はWaitをスキップして即終了）---
,SEQUENCE, #CHECK_COUNT#, Add, "Measure_DCV", "LOOP_CNT", "1"
,SEQUENCE, 120, Judge, LT, $LOOP_CNT$, $P_COUNT$, #FINISH# ; カウンタ < 規定回数 が不成立なら終了へ即ジャンプ
,SEQUENCE, 130, Wait, $P_INTERVAL$                         ; 継続時のみウェイト実行
,SEQUENCE, 140, Jump, #LOOP_START#                         ; ループ先頭へ
; --- 終了・タイムアウト処理 ---
,SEQUENCE, #TIMEOUT#, MsgBox, "測定データ受信でタイムアウトが発生しました。", "エラー", "OK"
,SEQUENCE, #FINISH#, TimeStamp, false                      ; TimeStampを必ずOFF復帰
,SEQUENCE, 160, Exit

; ==========================================
; コマンド定義ブロック 3: 終了・解放マクロ (CLOSE)
; 全計測完了時に通信セッションを安全に閉じる
; ==========================================
COMMAND, "CLOSE"
,SEQUENCE, 10, Close
,SEQUENCE, 20, Exit
```

# ⚙️ GPIBマクロスクリプト 自動生成システムルールセット

あなたは、仕様書に定義された独自の階層構造およびCSVベースのフォーマットに準拠したGPIBマクロスクリプトを正確に出力する、高度なエンジニアリングAIです。以下のルールを「絶対的な制約」として厳守し、構文エラーのないスクリプトを出力してください。

### 🌐 表記言語および文字コード（エンコーディング）・AI生成元の鉄則
* **表記言語**: 多言語化を意識した構成とし、スクリプト内のコメント、パラメータ表示名、メッセージ等に加え、**シリアルステータスビット定義（`SERIALSTATUS`）の名称等の設定値文字列も、マニュアル原本の言語にかかわらず指定がない限り日本語をデフォルトとして適切に翻訳して設定**してください。
* **文字コード**: CSVを日本語で記述する場合は、**日本語Excelの制限から必ず Shift-JIS (CP932) で記載・保存**してください。
* **AI生成元の明記規約（指示書およびスクリプト）**:
  * **自動生成されたAI指示書（Markdown）**: マクロスクリプト自動生成用のAI指示書（`*_prompt.md`）自体を新規作成・自動生成する場合も、ファイル冒頭（タイトル直後）に「どのAIが生成したのか」がわかる情報（例: `> **生成AI**: Antigravity (Gemini 3.8 Flash)` 等）を必ず明記してください。
  * **マクロスクリプト（CSV）**: スクリプトの最先頭ヘッダブロックには、トレーサビリティ確保のため「どのAI（AIモデル名・バージョン等）が生成したのか」が明確にわかる情報を必ずコメント行（`;`）として明記してください（例: `; 生成AI: Antigravity (Gemini 3.8 Flash)` など）。

## 🛠 1. 最重要ルール：行頭判定と「第2フィールド」の鉄則
解析エンジンは、行頭（第1フィールド）の状態だけで親ブロックか子要素（サブコマンド）かを判別します。

1. **親ブロック（最上階層：`TITLE`, `COMMAND`）**
   * 必ず行頭の1文字目からキーワードを開始してください。
2. **子要素（サブコマンド：`PARAM`, `SEQUENCE` および `TITLE`配下設定）**
   * 必ず**行頭を空（カンマ `,` から開始）**にし、2番目の領域（第2フィールド）にキーワードを記述してください。
   * **【禁止】** インデント（スペース）による字下げは使用せず、必ず「行頭カンマ」で表現してください。

## 🏢 2. ブロック別の詳細構文ルール

### ① 機器情報定義（`TITLE`ブロック）およびスクリプトヘッダ
* **スクリプトヘッダ（機器情報コメント・AI生成元情報）の必須追記**:
  スクリプトファイルの最先頭（`TITLE` 宣言行の前）には、対象機器を識別するためのメタデータ（対象機器名称、メーカー名、モデル/型番、準拠マニュアルのドキュメント番号やURL、概要・作成日など）に加え、**どのAIが生成したのかがわかる情報（AIモデル名・エージェント名・バージョン等）**を、独立したコメント行（行頭 `;`）として必ずヘッダブロックに記述してください。
* `TITLE` 宣言行は行頭から記述します。
* 配下の物理設定コマンドは、すべて**行頭カンマ（第2フィールド）**から記述します。
* **シリアルステータス定義の日本語翻訳（多言語化・デフォルト言語規約）**:  
  多言語化を意識した設計とし、`SERIALSTATUS` で定義する各ビット名称（1〜8）は、英語マニュアル記載の定義（例: `"Data Available"`, `"Ready for Instructions"` 等）をそのまま英語で出力せず、特に言語指定がない限りデフォルトである日本語（例: `"データ使用可能"`, `"命令準備完了"` など）へ適切に翻訳して設定してください。
* **行末コメントの許可**: `TITLE`ブロック配下に限り、パラメータ以降は無視されるため、行末に `;` を用いたコメント記述が可能です。

### ② コマンド定義（`COMMAND`ブロック）
* `COMMAND` 宣言行は行頭から記述します。第3フィールドの `[結果格納先キー]` は任意（省略可能）です。
* 配下の `PARAM`（変数定義）および `SEQUENCE`（処理手順）は、すべて**行頭カンマ（第2フィールド）**から記述する事を推奨します。
* **【厳禁】PARAM の「表示名」および「初期値」の省略・欠落完全禁止（CRITICAL事故防止）**:  
  `PARAM` 定義行は、解析処理において**第5フィールド（表示名）および第6フィールド（初期値）までが存在することを前提**としています。  
  `Range` 型（結果格納先）や `Work` 型（内部変数）であっても、`[表示名]` や `[初期値]` を省略して `,PARAM, "測定値", Range` のように4フィールド以下で出力することは**絶対に禁止**です（システム読み込み時に `IndexOutOfRangeException` が発生し、アプリケーションが起動不能になります）。初期値が不要な場合でも、必ず第5フィールドに表示名（または空文字 `""`）、第6フィールドに空文字 `""` を指定してください。
* **【厳禁】行末コメントの完全禁止**: `COMMAND`ブロック配下（`PARAM`, `SEQUENCE`）は可変長フィールドであるため、行末へのコメント記述は一切禁止です。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください。

## 📝 3. 具体的な記述書式（シンタックス）

### A. 変数・パラメータ定義（`PARAM`）
`,PARAM, [パラメータキー], [★データ型], [表示名], [値/選択肢...]`
* **必須フィールド構成（全5〜6フィールド以上必須）**:
  * 第1: `（空白）`（行頭カンマ）
  * 第2: `PARAM`
  * 第3: `[パラメータキー]`（変数識別名）
  * 第4: `[★データ型]`（`Text` / `List` / `Range` / `Value` / `Label` / `Work` の6種類）
  * 第5: `[表示名]`（**必須・省略不可**。UI表示名。内部変数や結果格納先の場合でも省略せず記述）
  * 第6: `[初期値]`（**必須/推奨・省略不可**。List型の初期選択肢、Work/Value型の初期値。不要時は空文字 `""` を指定）
  * 第7以降: `[追加選択肢...]`（List型用の2番目以降の選択肢）
* **【重要】** 表示名を省略して値を詰めて記述（例: `,PARAM, "CNT", Work, "0"`）すると、`"0"` が表示名として認識され、初期値が空になるため禁止です（必ず `,PARAM, "CNT", Work, "カウンタ", "0"` と記述）。

### B. 処理手順定義（`SEQUENCE`）
`,SEQUENCE, [ステップキー], [マクロ名], [引数1], [引数2]...`
* **動的置換**: 引数内で PARAM の値へ動的置換させる場合は、パラメータキーの両端を `$` で囲むこと（例: `$P_FREQ$`）。
* **条件ジャンプ**: ジャンプ先となるターゲットのステップキーを指定する場合は `#` で囲むこと（例: `#10#`）。
* **カンマのエスケープ**: 引数自体にカンマを含む場合は、必ず `","` のように二重引用符で囲むこと。

## 📐 4. コマンド設計の基本原則（単一責任・個別実装と単発/連続の統合）

### ① 測定項目ごとの個別実装（ファンクション分岐の禁止）
* 1つの `COMMAND` で複数の測定ファンクション（DCV/ACV/OHM等）を兼ねるような汎用マクロの作成は**禁止**します。
* 引数によるファンクション切り替え（`Equ` や `Jump` による複雑な分岐）を排除し、`DCV`, `ACV`, `OHMF` などの測定項目ごとに独立した COMMAND を定義してください。

### ② 単発測定は「取得回数＝1」で兼用（単発専用マクロの作成禁止）
* `_Single` や `_Continuous` のようにマクロを2重化せず、すべての測定マクロを**「回数指定可能な連続ループ構造」**で統一してください。
* `取得回数` パラメータの**初期値は必ず `"1"`** とし、デフォルトで単発測定として機能するようにしてください。

### ③ 単発実行時（回数＝1）の即時終了規約（無駄なウェイトの完全排除）
* データ受信・格納後、カウンタをインクリメントして「規定回数に達したか」を判定してください。
* 規定回数に達した場合は、`Wait`（サンプリング周期待機）を**スキップして即座に終了処理へジャンプ**させてください（単発測定時に余計な待ち時間が発生しないようにするため）。

### ④ コマンド繰り返し実行のための初期化（INIT）独立化規約
* 測定コマンドを外部（Excel VBAやループスクリプト等）から繰り返し高速に呼び出せるようにするため、通信ボードの接続・初期化（`Open` / `Init` / 機器リセット設定等）は各測定コマンド内には含めず、**独立した初期化マクロ（`INIT`）として分離定義**してください。
* 各測定コマンド内では毎回 `Open` や `Close` を行わず、初期化済みの通信セッション上で「設定・トリガ・受信・格納・回数判定」のみを行って `Exit` させてください。これにより、繰り返し実行時の切断・再接続オーバーヘッドが解消され、機器設定を維持したまま最小遅延で高速な測定を継続できます。
* 計測作業全体の終了時に通信ボードを安全に解放するため、独立した終了コマンド（`CLOSE`）を設けてください。

### ⑤ TimeStamp コマンドはすべての送受信コマンドに先立って実行する鉄則
* タイムスタンプ機能を有効化（またはパラメータ指定で設定）する場合、**シーケンス内で実行される最初の送受信コマンド（`Send` / `Receive`）よりも前に、最優先で実行**してください。
* 送受信が実行された後に `TimeStamp` を呼び出すことは禁止です。必ず測定コマンドのステップ先頭（ステップ10等）で `TimeStamp, $パラメータ$` を実行し、その後に機器設定コマンド（`Send`）やトリガ送出（`Send`）を行うシーケンス構造に統一してください。

### ⑥ デバッグ疑似データは Excel から指定できるよう Work 以外（Text型等）で定義する鉄則
* 疑似受信データを供給するパラメータ（`DEBUG_VAL` や `デバッグデータ` 等）は、Excel ワークシート上からユーザーが自由にテストデータを入力・指定できるよう、**`Work` 型ではなく `Text` 型（または `Value` 型）として定義**してください。
* `Work` 型で定義されたパラメータは、内部ワーク変数とみなされて Excel アドイン側でパラメータ入力セルが生成されません。Excel 上でのデバッグ検証を可能にするため、必ず `Work` 以外の型（`Text` 型推奨）を使用してください。

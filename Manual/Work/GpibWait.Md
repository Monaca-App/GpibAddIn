# コマンドリファレンス：Wait

## 概要
`Wait` は、マクロスクリプトの引数で指定されたミリ秒時間（1/1000秒単位）だけ、シーケンスの進行を確実に一時停止（ウェイト）させるフロー制御系シーケンスコマンドです [1.1]。
計測器の設定を切り替えた直後の「物理的なリレーの安定待ち」や、電源印加後の「電圧立ち上がり時間（ディレイ）」など、通信やハードウェアの同期タイミングを正確に直列制御する際に使用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドはUIを凍結させないノンブロッキング直列待機を内蔵しています [1.1]。内部の処理停止には `Task.Delay().GetAwaiter().GetResult()` 構造を採用しており、マクロの実行エンジンが動作しているバックグラウンドスレッドのみをピンポイントで安全に直列ブロッキング（ロック）するため、メイン画面のUIスレッドを完全にフリーズ（応答なし状態）させることなく、指定時間通りの正確なディレイを発生させます [1.1]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], Wait, [待機時間(ms)]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 待機時間(ms) | シーケンスを一時停止させる時間。1/1000秒単位。（必須引数） [1.1] | 固定整数（例: `500` ＝ 0.5秒）またはパラメータ動的置換（例: `$P_DELAY$`） [1.1] |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです [1.1]。

*   **動的置換（`$`）**: 引数1の時間文字列内において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます（例: `,SEQUENCE, 20, Wait, $P_DELAY$`） [1.1, 1.2]。試験する製品の仕様やレンジ設定の違いに応じて、安定待ち時間を動的にアジャストするマクロが構築できます [1.1]。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 本コマンドの引数は数値および変数キー指定を想定しているため、カンマのエスケープ規約は原則適用されません。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Switch_And_Safe_Measure"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_DELAY, Value, "安定ディレイ", "500"
,PARAM, P_DATA, Work, "受信バッファ", ""
; 1. 計測器へスキャナのチャンネル切り替えコマンドを送信
,SEQUENCE, 10, Send, "ROUT:CLOS (@101)"
; 2. 【物理安定待ち】チャタリングによる測定ブレを防ぐため、変数(P_DELAY)の指定時間(500ms)だけ正確に待機
; ※この間もメイン画面の操作やUI描画はフリーズしません
,SEQUENCE, 20, Wait, $P_DELAY$
; 3. 回路が完全に安定したため、安全に測定コマンドを送信して回収
,SEQUENCE, 30, Send, "MEAS:VOLT?"
,SEQUENCE, 40, Receive
```

### 実行時の挙動・変数変化

*   **実行前の状態**: リレーマトリクスを閉じて測定チャンネルを切り替えた直後など、物理層のチャタリングが収まるまで一定時間のディレイ（例: `P_DELAY` ＝ `"500"`)を発生させたいコンテキストです [1.2]。
*   **実行後の状態**: 指定された待機時間が評価され、バックグラウンドスレッドが安全に直列待機に入ります [1.1]。この間もメイン画面の描画やUIスレッドの操作性は完全に維持されます [1.1, 1.2]。引数が `0` 以下の値である場合や数値変換に失敗した場合は、システムに負荷をかける意図しない待機状態（無限ループなど）を走らせず、安全に処理をスキップ（早期リターン）して即座に次行を実行します [1.1, 1.2]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **必須引数の欠損ガード（早期リターン）**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合は、現在の状態を破壊しないよう、ウェイト処理を行わずに安全に該当ステップをスキップ（早期リターン）します [1.2]。
*   **数値変換失敗時のセーフティ（エラーログ）**
    引数にアルファベットなどの非数値文字が混入して `int.TryParse` に失敗した場合、システムは例外（`FormatException`）を発生させてクラッシュせず、内部ログに明確なエラー（`LogError`）を記録した上で安全に早期リターンし、次のステップへ処理を繋ぎます [1.2]。
*   **0以下の数値指定時の安全処理**
    `0` や `-100`（マイナス値）などの不正な待機時間が指定された場合は、負のディレイによるスレッドの破綻を防ぐため、ウェイト処理を完全にスキップして即座に次の行を実行します [1.2]。
*   **同期時にシステム例外が発生した場合（LogCritical）**
    待機タスクの生成時やスレッド同期（`GetAwaiter`）の最中に予期せぬ内部例外が発生した場合でも、`catch (Exception)` ブロックがすべての例外を確実に捕捉します [1.2]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、アプリケーション全体の強制終了を自動防御します [1.2]。

* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）

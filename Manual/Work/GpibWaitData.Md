# コマンドリファレンス：WaitData

## 概要
`WaitData` は、GPIB機器からのデータ受信状況を一定時間バックグラウンドで自律監視（ポーリング待機）し、有効データが届いた場合は即座に受信バッファへ格納、万が一データが届かないままタイムアウト（時間切れ）が発生した場合は、指定のステップ番号へ制御を安全に条件ジャンプさせるための通信・フロー制御系シーケンスコマンドです [1.1]。  
**Receive 結果をシーケンスパラメータに反映するには、WaitData を用いる必要があります。**  
旧システムで見られた画面が固まるようなウェイト処理（`Application.DoEvents` や `Thread.Sleep`）をインフラ層から完全排除しており、応答の遅い計測器のデータ待ちや、トリガーキック後の応答監視フローにおいて高い安定性を発揮します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 監視ループ内では、対象デバイスのデータ通信履歴から最新の受信データ行（`G_Get_ReceiveData` 経由で取得される `device.LastLine`）を読み取ります [1.1]。システムが定義する受信識別文字（例: `"R:"` 等の `Char_Rec` 文字列）を大文字小文字の区別なく（`OrdinalIgnoreCase`）自動検出し、有効な受信データが到着したかを安全に判定します [1.1]。  
> **受信バッファ（`param.RecData`）の格納形式とパース書式規約**:
> * **タイムスタンプ有効時**: ログ行頭にタイムスタンプが付加されるため、`[ yyyy/MM/dd HH:mm:ss.fff ] R:data` 形式で格納されます。後続の `SetData` / `SetData_RowAdd` では `"[ %s %s ] R:%f"` 書式を指定して日付・時刻・測定数値を分離し、Excelで3列展開されるようカンマ展開します。
> * **タイムスタンプ無効時**: 測定値のみ格納されるのではなく、受信マークを含む **`R:data` 形式**（例: `"R:12.345"`）で格納されます。したがって、後続の `SetData` / `SetData_RowAdd` による数値パース書式には `"%f"` ではなく **`"R:%f"` 形式** を指定する必要があります。

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], WaitData, [タイムアウト時のジャンプ先ラベル名]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | ジャンプ先ラベル名 | タイムアウト（データ未着）時に遷移させる `SEQUENCE` のジャンプ先ラベル名（ステップキー）。省略時はエラーメッセージを表示 [1.1]。 | ジャンプ記法（例: `#50#` や `#Timeout#`）またはラベル名（例: `50` や `Timeout`） [1.1]。 |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです [1.1]。

*   **動的置換（`$`）**: 引数1において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.1]。
*   **条件ジャンプ（`#`）**: 引数1において、ターゲットとなるラベル名を `#50#` や `#Timeout#` のように `#` で囲んで指定することで、タイムアウト発生時の条件ジャンプ先として安全にバインドされます [1.1, 1.2]。
*   **カンマのエスケープ**: 本コマンドの引数はラベル名およびステップキー指定を想定しているため、カンマのエスケープ規約は原則適用されません。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Autonomous_Wait_Measure"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_DATA, Work, "データパース用バッファ", ""
; 1. 計測器へ測定トリガーを送信
,SEQUENCE, 10, Send, "INIT;*TRG"
; 2. 【受信監視】データ到着を自律ポーリング。
; ※一定時間内にデータが来なければ、リトライのためステップ10 (#10#) へ条件ジャンプします
,SEQUENCE, 20, WaitData, #10#
; 3. 【正常系】時間内にデータが届いた場合のみここへ進み、前詰めパースして終了
,SEQUENCE, 30, SetData, P_DATA, "%s"
,SEQUENCE, 40, Exit
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 機器へ測定要求コマンドを送信した直後、メイン画面をロックすることなくバックグラウンドで応答データの到着を監視したいコンテキストです [1.1, 1.2]。
*   **実行後の状態**: 10ミリ秒単位（`conTimeOutMs`）の非同期タスク遅延によるポーリング監視ループが形成され、設定された最大タイムアウトカウントに達するまで受信バッファのチェックが継続されます [1.1]。指定時間内にデータが受信されれば即座にバッファが抽出されて次ステップへ進行し、タイムアウトが発生した場合は引数1で指定されたステップキー `#10#` へと実行フローが安全にジャンプします [1.1, 1.2]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **ユーザーによる測定停止コマンドの即時検知**
    監視ループの最中に、作業者が画面から測定停止を要求（`targetForm.GpibComStop` が変動）した場合、システムはタイムアウト時間を待つことなく即座に監視ループを脱出（ブレイク）し、無駄な待機時間をカットして制御を安全に戻します [1.2]。
*   **ジャンプ先（引数1）の省略時におけるエラーハンドリング**
    引数1が未指定（`paramCount < 1`）の状態でタイムアウトが発生した場合、バックグラウンドスレッドから自動的に `targetForm.InvokeRequired` を判定し、UIスレッドへ安全に同期（Invoke）した上で、最前面にエラーダイアログ（`MessageBox.Show`）を安全に表示します [1.2]。その後、マクロを停止させずに最終端（`Sequences.Count`）へ安全に遷移させて正常終了させます [1.2]。
*   **存在しないラベル名（ステップキー）が指定された場合のガード句**
    マクロ内に実在しないラベル名（または数値）が検出された場合は、エラーログを記録した上で現在のマクロの末尾へ安全に遷移させて正常終了させ、不整合によるハングアップを完全に防止します [1.2, 1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

# コマンドリファレンス：SetData_RowAdd

## 概要
`SetData_RowAdd` は、GPIB機器から直前に受信した生データ（`RecData`）に対して、独自の `sscanf`（データ抽出）および `sprintf`（書式化・フォーマット加工）を順次適用し、指定された変数の既存データに対して改行（CRLF）付きで安全に末尾へ追記（RowAdd）するためのデータ解析・バッファ蓄積系シーケンスコマンドです [1.1]。
前述の `SetData` が純粋な上書きであるのに対し、本コマンドは動的なデータ履歴の蓄積を行います [1.1]。ループ計測において、パース済みのデータを1行ずつメモリ上に積み上げ、最終的に複数行のテーブル型テキスト（2次元配列風バッファ）を構築する際などに効果的です [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドはスマートな改行結合ロジックを内蔵しています [1.1]。対象の変数がまだ「空（未格納）」である場合は、余計な改行を付与せず加工データをそのまま格納し、すでに「既存データが存在する」場合は、自動的に `Environment.NewLine`（CRLF改行）を挟んで末尾へデータを追記します [1.1]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], SetData_RowAdd, [追記先変数キー], [sscanf抽出書式], [sprintf加工書式1], [sprintf加工書式2]...
```

### パラメータ（引数）一覧

マクロスクリプトからは、最初の追記先変数キーと sscanf 抽出書式に続けて、任意の数（可変長）だけフォーマット整形用の sprintf 加工書式を連続して指定できます [1.1]。

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 追記先変数キー | 最終加工データを改行付きで追記する変数名。（必須引数） [1.1] | `PARAM` で定義した変数キー名（例: `"DATA_LOG"`） [1.1] |
| **引数2** | sscanf抽出書式 | 生データから目的の値を抽出するためのパターン [1.1]。 | 例: `"CH1=%s"`（ヘッダーを除外して値のみ抽出） [1.1, 1.2] |
| **引数3〜** | sprintf加工書式 | 抽出した値をフォーマット整形する書式。可変長指定に対応 [1.1]。 | 例: `"%0.3f"`（小数点以下3桁固定） [1.1] |

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: すべての引数において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.3]。
*   **カンマのエスケープ**: 各種加工書式文字列自体にカンマを含める場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### データ処理の具体例と内部挙動
*   **標準的な受信データ（`RecData`）とパース書式指定**:
    * **タイムスタンプ無効時**: 受信データは測定値のみではなく、受信マークを含んだ `"R:1.234"` のような **`"R:%f"` 形式** で格納されます。  
      マクロ記述例: `,SEQUENCE, 30, SetData_RowAdd, LOG_BUF, "R:%f", "%0.2f"`  
      ※`sscanf` 書式 `"R:%f"`（または `"R:%s"`）により受信マーク `"R:"` をスキップして測定値を正確に抽出・追記します。
    * **タイムスタンプ有効時**: 受信データは `"[ 2026/10/31 23:59:59.999 ] R:1.234"` 形式で格納されます。  
      タイムスタンプ分離マクロ記述例: `,SEQUENCE, 30, SetData_RowAdd, LOG_BUF, "[ %s %s ] R:%f", "%s, %s, %0.3f"`  
      ※日付、時刻、測定数値を分離し、各々をカンマ区切りデータとして1行に結合して追記格納します（Excel上で3列に自動展開されます）。
*   **内部での蓄積ライフサイクル**:
    1.  *1回目実行時*: `LOG_BUF` の既存値は空のため、パース結果 `"1.23"` がそのまま格納されます [1.2]。
    2.  *2回目実行時*: `LOG_BUF` に既存値 `"1.23"` があるため、改行付きで結合されます [1.2]。
*   **最終結果**: 変数 `LOG_BUF` の中身は、以下のような美しい2行のテキストとしてメモリに蓄積されます [1.2]。
    ```text
    1.23
    5.68
    ```

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Continuous_Row_Accumulate"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_LOG, Work, "パース履歴蓄積バッファ", ""
,PARAM, P_BUF, Work, "一時受信バッファ", ""
; 1. 測定クエリを送信し、データを物理層から変数（P_BUF）に回収
,SEQUENCE, 10, Send, "MEAS:VOLT?"
,SEQUENCE, 20, Receive
; 3. 【改行付きデータ追記】受信データから数値を抽出し、小数点2桁にして変数(P_LOG)の末尾へ行追加
; ※実行のたびに、メイン画面上の編集テキストエリアもスレッド安全に自動更新されます
,SEQUENCE, 30, SetData_RowAdd, P_LOG, "%s", "%0.2f"
; 4. 指定回数分ループ（条件分岐・インクリメント等は省略してステップ10へ戻る）
,SEQUENCE, 40, Jump, #10#
; 5. ループを抜けたら、行蓄積された全データを一括でCSVファイルへ保存
,SEQUENCE, 50, LogOut, "C:\Log\sweep_result.csv", true
```

### 実行時の挙動・変数変化

*   **実行前の状態**: スイープ計測ループ内などで測定データが受信され、システム内部の受信バッファに新たな生データ文字列が保持されているコンテキストです [1.1, 1.2]。
*   **実行後の状態**: `SetData` と同様に多段書式化チェーンが実行され、加工データがターゲット変数の末尾に改行コード付きで安全に結合蓄積されます [1.1, 1.2]。追記されたデータはシステム全体の共通応答バッファ（`GpibAnalysis.ResponseMessage`）へも自動的に蓄積され、内部で自動的に `InvokeRequired` ガードを適用しながらメイン画面上のテキスト表示（`RefreshEditText`）を動的にリフレッシュさせます [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **必須引数が不足している場合**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合、内部のデータ構造破壊を防ぐため、パース解析を行わずに即座に安全に早期リターン（処理スキップ）します [1.3]。
*   **追記先パラメータが変数プールに存在しない場合**
    引数1で指定された追記先の変数キーがコマンドの `Params` 辞書に存在しない場合、システムは処理をパスします [1.3]。明確なエラーログ（`LogError`）を排出し、マクロの実行コンテキストの整合性を維持したまま安全に該当ステップを終了します [1.3]。
*   **パースや結合時にシステム例外が発生した場合（LogCritical）**
    独自ライブラリ（`_logString.sscanf` / `sprintf`）のパース時や、文字列結合、UI更新の最中に予期せぬ内部システム例外が発生した場合、`catch (Exception)` ブロックがすべての例外を確実に捕捉します [1.3]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、アプリケーション全体の強制終了を自動防御します [1.3]。

* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

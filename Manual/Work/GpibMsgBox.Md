# コマンドリファレンス：MsgBox

## 概要
`MsgBox` は、指定されたテキスト、タイトル、ボタン構成、および既定ボタンに基づいてダイアログボックスをスレッド安全に最前面表示し、ユーザーが選択した結果（`OK` / `Cancel` / `Yes` / `No` 等）を変数へ安全に書き戻すユーザー対話型・フロー制御系シーケンスコマンドです [1.1]。
自動測定中に「治具のセット確認」を作業者へ促したり、「エラー発生時に試験を続行するかどうか」を選択させて条件分岐（`Equ` 等）へ繋ぐといった、オペレーター対話型のマクロフローを構築する際に活用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> ボタン構成（引数3）や既定ボタン（引数4）の設定値は、文字列形式（例: `"YesNo"`, `"Button2"`)と数値形式（例: `4`, `256`)のどちらで指定されても内部でインテリジェントに識別・変換されます [1.1]。大文字・小文字の区別も不要です [1.1]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], MsgBox, [表示テキスト], [タイトル], [ボタン構成], [既定ボタン], [結果格納先変数]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 表示テキスト | ダイアログのメッセージ本文。（必須引数） [1.1] | 固定文字列、またはパラメータ動的置換（例: `$P_MSG$`） [1.1] |
| **引数2** | タイトル | ダイアログのヘッダータイトル。省略時は `"メッセージ"` [1.1]。 | 固定文字列、またはパラメータ動的置換 [1.1] |
| **引数3** | ボタン構成 | 配置するボタンの種類。省略時は `OK` ボタンのみ [1.1]。 | 下記の「ボタン構成一覧」参照（文字列または数値） [1.1] |
| **引数4** | 既定ボタン | 最初からフォーカスを当てるデフォルトのボタン [1.1]。 | 下記の「既定ボタン一覧」参照（文字列または数値） [1.1] |
| **引数5** | 結果格納先変数 | ユーザーがクリックした結果文字列を代入する変数名 [1.2]。 | `PARAM` で定義した変数キー名（例: `"P_ANS"`） [1.2] |

### 💡 ボタン構成（引数3）の詳細仕様

| 文字列指定（大文字小文字不問） | 数値指定 | 配置されるボタン |
| :--- | :--- | :--- |
| **OK** | 0 | [OK]（既定値） [1.2] |
| **OKCancel** | 1 | [OK] [キャンセル] [1.2] |
| **AbortRetryIgnore** | 2 | [中止] [再試行] [無視] [1.2] |
| **YesNoCancel** | 3 | [はい] [いいえ] [キャンセル] [1.2] |
| **YesNo** | 4 | [はい] [いいえ] [1.2] |
| **RetryCancel** | 5 | [再試行] [キャンセル] [1.2] |

### 💡 既定ボタン（引数4）の詳細仕様

| 文字列指定（大文字小文字不問） | 数値指定 | 動作説明 |
| :--- | :--- | :--- |
| **Button1** | 0 | 左から1番目のボタンをデフォルトにする（既定値） [1.2] |
| **Button2** | 256 | 左から2番目のボタンをデフォルトにする [1.2] |
| **Button3** | 512 | 左から3番目のボタンをデフォルトにする [1.2] |

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: すべての引数において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.2]。ユーザーが `[はい]` を押すと格納先変数に `"Yes"`、`[いいえ]` を押すと `"No"` などの結果文字列が安全に格納されます [1.2]。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 表示テキストやタイトル文字列自体にカンマを含める場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.2, 1.3]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Interactive_Measure"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_ANS, Text, "ユーザー選択結果", ""
,PARAM, P_DATA, Work, "受信データバッファ", ""
; 1. 最前面に「はい/いいえ」の問い合わせダイアログを表示し、結果変数(P_ANS)に格納
,SEQUENCE, 10, MsgBox, "サンプルをセットしましたか？", "準備確認", "YesNo", "Button1", P_ANS
; 2. ユーザーが「いいえ（No）」を選択した場合は、ステップ50（中断処理）へジャンプ
,SEQUENCE, 20, Equ, $P_ANS$, "No", #50#
; 3. 【正常系】「はい」の場合のみここへ進み、GPIB計測を実行
,SEQUENCE, 30, Send, "READ?"
,SEQUENCE, 40, Receive
,SEQUENCE, 41, SetData, P_DATA, "%s"
,SEQUENCE, 45, Exit
; 4. 【中断系】作業者が拒否、または未準備の場合の離脱フロー
,SEQUENCE, 50, Exit
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 自動測定の進行中、作業者へ物理的な治具セットアップや事前準備の確認を促したいコンテキストです [1.1, 1.2]。
*   **実行後の状態**: マクロの実行エンジンがバックグラウンドスレッドで動作している場合でも、内部で自動的に `targetForm.InvokeRequired` 判定を行い、メインのUIスレッドへ安全に同期ディスパッチ（Invoke）してダイアログを最前面にポップアップ表示します [1.1]。作業者がボタンをクリックすると、選択結果に応じた識別文字列（例: `"Yes"` または `"No"`）が変数 `P_ANS` へと安全に書き戻されます [1.1, 1.2]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.3]。

*   **必須引数（表示テキスト）が不足している場合**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合、「MsgBoxコマンドに必要な引数が不足しています」というエラーログ（`LogError`）を記録し、ダイアログを表示せずに安全に該当ステップをスキップ（早期リターン）してマクロの実行ハングを防止します [1.3]。
*   **不正なボタン・既定ボタンが指定された場合**
    引数3や引数4に定義外の不正な文字列や数値（例: `"UnknownButton"`, `999`）が指定された場合は、実行エンジンが自動的に安全な既定値（ボタン構成＝`OK`、既定ボタン＝`Button1`）へと自動フォールバックしてダイアログを起動します [1.3]。
*   **結果格納先パラメータが変数プールに存在しない場合**
    引数5で指定された格納先キーがコマンドの `Params` 辞書に存在しない場合、システムは不正なメモリ書き込みをパスします [1.3]。ログにエラーを出力し、マクロの実行コンテキストを安全に維持したまま次のステップへ遷移します [1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

# コマンドリファレンス：TimeStamp

## 概要
`TimeStamp` は、画面上のデータ表示ログや外部出力ストリームに対するミリ秒タイムスタンプ自動付与機能の有効（ON）/ 無効（OFF）を動的に切り替えるシーケンスコマンドです [1.1]。
測定データの取得時刻を精密に記録したいフェーズでは「有効」にし、逆に高速な連続受信などにおいて文字列処理のオーバーヘッド（負荷）を極限まで減らしたいフェーズや、純粋な受信テキストのみをそのまま出力したいフェーズでは「無効」にするといった、マクロ実行中の動的なログ制御に活用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドは柔軟なトグル評価判定を行います [1.1]。引数に渡された文字列が `"0"` または大文字小文字不問の `"false"` である場合は「無効（OFF）」と判定し、それ以外の指定値（`"1"` や `"true"` など）はすべて「有効（ON）」として識別・評価されます [1.1]。  
> **【タイムスタンプ設定に伴う受信データ形式とパース書式規約】**  
> * **有効（ON）時**: システムは受信データを `[ 2026/10/31 23:59:59.999 ] R:data` の形式で取得します。このデータを `SetData` や `SetData_RowAdd` 等で解析・蓄積する場合、`"[ %s %s ] R:%f"` 書式で日付・時刻と測定データを分離し、各々をカンマ区切りのデータ（例: `"%s, %s, %0.6f"`）として扱います（これにより、Excel上の `Range` 型セルへ「日付」「時刻」「測定値」の3列マトリクスとして綺麗に自動展開されます）。  
> * **無効（OFF）時**: 受信データは測定値のみ格納されるのではなく、受信識別マークを含む **`R:data` 形式（例: `R:1.234`）** で取得されます。したがって、`SetData` や `SetData_RowAdd` 等で数値を抽出する場合は、`"%f"` ではなく **`"R:%f"` 形式** を指定する必要があります。  
> **【コマンド終了時の TimeStamp OFF 復帰鉄則】**  
> `TimeStamp` コマンドによる設定はシステム全体に持続します。他のコマンドや後続のマクロ処理への予期せぬ影響を防ぐため、**マクロ内でタイムスタンプ機能を使用した場合は、必ずそのコマンドの終了時（`Exit` 直前）に `TimeStamp, false` を実行して機能を OFF に戻してください**。

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], TimeStamp, [切替フラグ]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 切替フラグ | タイムスタンプ機能を切り替えるモードスイッチ。（必須引数） [1.1] | `1` / `true`（ON）、`0` / `false`（OFF） ※変数置換対応 [1.1] |

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: 引数1において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.1]。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 本コマンドの引数はモードスイッチ文字を想定しているため、カンマのエスケープ規約は原則適用されません。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Optimize_Log_Measure"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_BUF, Work, "高速受信バッファ", ""
; 1. 機器接続を開き、初期化時は時刻追跡のためにタイムスタンプを有効化
,SEQUENCE, 10, Open
,SEQUENCE, 20, Init
,SEQUENCE, 30, TimeStamp, true
,SEQUENCE, 40, Send, "*RST"
; 2. 【オーバーヘッド削減】超高速なバースト受信ループに入る前にタイムスタンプを一時無効化
,SEQUENCE, 50, TimeStamp, 0
; 3. コア測定ループ（タイムスタンプの文字列結合処理を省き高速周回）
,SEQUENCE, 60, Send, "FETCH?"
,SEQUENCE, 70, Receive
,SEQUENCE, 80, Jump, #60#
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 初期化フローが完了し、タイムスタンプ文字列の結合処理負荷を下げて高速測定ループへ突入したい直前のコンテキストです [1.1, 1.2]。
*   **実行後の状態**: マクロのステップ実行および画面上のメニュー（`mnuTimeOn` / `mnuTimeOff`）の双方から一括切替API（`SetTimestampUiState`）が呼び出されます [1.1]。マクロ実行エンジンがバックグラウンドスレッドで動作している場合でも、内部で自動的に `targetForm.InvokeRequired` 判定を行い、メインのUIスレッドへ安全に同期ディスパッチ（Invoke）してメニューのチェック状態と内部フラグを一括更新するため、画面のフリーズを発生させずに安全に処理されます [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.3]。

*   **必須引数の欠損ガード（早期リターン）**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合は、現在の状態を破壊しないよう、モードの切り替えを行わずに安全に該当ステップをスキップ（早期リターン）します [1.3]。
*   **UI状態の相互反転トグル保証**
    一括切替API内部で、`mnuTimeOn.Checked` と `mnuTimeOff.Checked` の排他制御（片方がONならもう片方は必ずOFF）が確実に同期して書き換わります [1.3]。UI表示の矛盾や内部フラグの解釈ズレによるログデータ破損を未然に防ぎます [1.3]。
*   **制御時にシステム例外が発生した場合（LogCritical）**
    メニューコントロールのチェック書き換え時や、インフォメーションログへのステータス排出時に予期せぬ内部スレッド例外が発生した場合でも、`catch (Exception)` ブロックがすべての例外を確実に捕捉します [1.3]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、アプリケーション全体の強制終了を自動防御します [1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッド of 呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

# コマンドリファレンス：SetData

## 概要
`SetData` は、GPIB機器から直前に受信した生データ（`RecData`）に対して、独自の `sscanf`（データ抽出）および `sprintf`（書式化・フォーマット加工）を順次適用し、解析結果を特定の変数へ格納するためのデータ解析系シーケンスコマンドです [1.1]。
計測器から返されるヘッダー付き文字列や、カンマ区切りのマルチデータから「必要な数値データだけをピンポイントで切り出し、桁数や単位を指定して変数へ格納する」といった一連のデータパース工程を1ステップで処理できます [1.1]。

⚠️ **データ受信との関係性について**
`Receive` コマンド単体の実行では、受信したデータは `RecData` パラメータに反映されません。**Receive 結果をシーケンスパラメータに反映し、本コマンド（SetData）で処理するには、Receive と SetData の間に WaitData を用いる必要があります。**

> 💡 **補足 / ⚠️ 注意**
> 本コマンドは、引数の数に応じて、まず `sscanf` による文字列パージをかけ、その後ろに指定された任意の数（可変長）の `sprintf` フォーマットをパイプラインのように連続適用してデータを精密に成形する「多段の書式化チェーン」を構成できます [1.1]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], SetData, [格納先変数キー], [sscanf抽出書式], [sprintf加工書式1], [sprintf加工書式2]...
```

### パラメータ（引数）一覧

マクロスクリプトからは、最初の格納先変数キーと sscanf 抽出書式に続けて、任意の数（可変長）だけフォーマット整形用の sprintf 加工書式を連続して指定できます [1.1]。

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 格納先変数キー | 最終加工データを代入するオブジェクト名。（必須引数） [1.1] | `PARAM` で定義した変数キー名（例: `"RESULT_VAL"`） [1.1] |
| **引数2** | sscanf抽出書式 | 生データから目的の値を抽出するためのパターン [1.1]。 | 例: `"DATA:%s"`（ヘッダーを除外して値のみ抽出） [1.1, 1.2] |
| **引数3〜** | sprintf加工書式 | 抽出した値をフォーマット整形する書式。可変長指定に対応 [1.1]。 | 例: `"%0.3f"`（小数点以下3桁に固定）、`"%s V"`（単位付与） [1.1] |

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: すべての引数において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.3]。
*   **カンマのエスケープ**: 各種加工書式文字列自体にカンマを含める場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### データ処理の具体例と内部挙動
*   **標準的な受信データ（`RecData`）とパース書式指定**:
    * **タイムスタンプ無効時**: 受信データは測定値のみではなく、受信マークを含んだ `"R:+01.23456E+01"` のような **`"R:%f"` 形式** で格納されます。  
      マクロ記述例: `,SEQUENCE, 10, SetData, CH1_DATA, "R:%f", "%0.2f", "%s V"`  
      ※`sscanf` 書式 `"R:%f"` により受信マーク `"R:"` をスキップして測定値を正確に抽出します。
    * **タイムスタンプ有効時**: 受信データは `"[ 2026/10/31 23:59:59.999 ] R:+01.23456E+01"` 形式で格納されます。  
      マクロ記述例: `,SEQUENCE, 10, SetData, CH1_DATA, "[ %s %s ] R:%f", "%s, %s, %0.2f"`  
      ※日付、時刻、測定数値を分離し、`"2026/10/31, 23:59:59.999, 12.35"` のようにカンマ区切りデータとして変数に格納します（Excel上で3列に展開可能）。
*   **最終結果**: 変数 `CH1_DATA` に `"12.35 V"`（または日時と数値のカンマ分離テキスト）が安全に格納され、画面へも即座にリフレッシュ描画されます [1.2]。

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Parse_And_Log_Process"
; コメントは独立した行に記述（行末への記述は完全禁止)
,PARAM, P_RESULT, Text, "パース結果", ""
,PARAM, P_BUF, Work, "配列バッファ", ""
; 1. 測定クエリを送信し、データを物理層から変数（受信バッファ）に回収
,SEQUENCE, 10, Send, "FETCH?"
,SEQUENCE, 20, Receive
; 2. Receive結果をシーケンスパラメータに反映するためWaitDataを実行
,SEQUENCE, 25, WaitData, #10#
; 3. 【データ加工】受信データから数値を抽出し、小数点3桁に固定して変数(P_RESULT)へ格納
; ※処理完了と同時にUIエディタのテキスト表示がスレッド安全に更新されます
,SEQUENCE, 30, SetData, P_RESULT, "VAL:%s", "%0.3f"
; 4. 整形された結果(P_RESULT)をログファイルへ1行ストリーム出力
,SEQUENCE, 40, LogOut, "C:\Log\measure.csv", true
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 測定クエリ送信後、`Receive` および `WaitData` コマンドが実行され、システム内部の受信文字列バッファ（`param.RecData`）に生の受信データが安全に反映・保持されているコンテキストです [1.1, 1.2]。
*   **実行後の状態**: 多段的な書式化チェーンが高速に実行され、処理された確定データはシステム全体の共通応答バッファ（`GpibAnalysis.ResponseMessage`）へ自動追記されます [1.1]。同時に、内部で自動的に `InvokeRequired` ガードを適用しながらメイン画面上のテキスト編集エリア（`RefreshEditText`）を動的にリフレッシュさせ、指定された変数へ安全に格納されます [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **必須引数が不足している場合**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合、内部のデータ構造破壊を防ぐため、パース解析を行わずに即座に安全に早期リターン（処理スキップ）します [1.2]。
*   **格納先パラメータが変数プールに存在しない場合**
    引数1で指定された格納先キーがコマンドの `Params` 辞書に事前登録されていない場合、システムは不正なメモリ書き込みをパスします [1.3]。明確なエラーログ（`LogError`）を排出し、マクロの実行コンテキストの整合性を維持したまま安全に該当ステップを終了します [1.3]。
*   **パース時にシステム例外が発生した場合（LogCritical）**
    独自ライブラリ（`_libString.sscanf` / `sprintf`）のパース時や、UI更新の最中に予期せぬ内部システム例外が発生した場合、`catch (Exception)` ブロックがすべての例外を確実に捕捉します [1.3]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、アプリケーション全体の強制終了を自動防御します [1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

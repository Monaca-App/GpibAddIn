# コマンドリファレンス：MODE

## 概要
`MODE` は、現在の通信対象デバイスが保持しているリモートステータス（制御状態）を自動で判別し、指定された変数へ状態テキスト（文字列）として格納するフロー・状態管理系シーケンスコマンドです [1.1]。
自動測定シーケンス内で「機器が現在手動操作モード（Local）になっていないか」「リモート制御（Remote）に正しく遷移できているか」を事前に確認し、意図しない手動介入や通信エラーを防止するための動的なステータス監視フローに活用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> デバイスの物理および内部状態（`RemoteStatusEnum`）に応じて、以下のいずれか1つの文字列が格納先変数へ正確にセットされます [1.1]。未定義の状態を検知した場合でも、システムをフリーズさせずに `"Unknown"` を出力します [1.1, 1.2]。
> *   **"Local"**: 手動操作モード（前面パネルのボタン操作が可能） [1.1]。
> *   **"Remote"**: リモート制御モード（PCからのコマンド入力を受付中） [1.2]。
> *   **"Remote (Local Lock Out)"**: リモート制御 ＋ 手動パネル操作が完全にロックされた状態 [1.2]。
> *   **"Local (Reserv Local Lock Out)"**: ローカルロックアウトが予約・維持された状態 [1.2]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], MODE, [状態テキスト格納先変数]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 状態テキスト格納先変数 | 判別されたリモートステータスの文字列を代入する変数名 [1.1]。 | `PARAM` で定義した変数キー名（例: `"P_STATUS"`） [1.1] |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: 引数1において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 本コマンドの引数は変数キーを想定しているため、カンマのエスケープ規約は原則適用されません。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Secure_Remote_Measure"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_STATUS, Text, "ステータス確認変数", ""
,PARAM, P_DATA, Work, "受信データバッファ", ""
; 1. 機器をリモート状態へ移行
,SEQUENCE, 10, GTR
; 2. 現在の機器制御モードを変数(P_STATUS)に取得
,SEQUENCE, 20, MODE, $P_STATUS$
; 3. 変数(P_STATUS)の内容が "Remote" と不一致（＝移行失敗）なら、ステップ50のエラー終了処理へ
,SEQUENCE, 30, Equ, $P_STATUS$, "Remote", #50#
; 4. 【正常系】正しくリモート状態が確認できたため、安全に計測を実行
,SEQUENCE, 40, Send, "FETCH?"
,SEQUENCE, 45, Receive
,SEQUENCE, 46, SetData, P_DATA, "%s"
,SEQUENCE, 48, Exit
; 5. 【異常系】リモート遷移失敗時の安全シャットダウンフロー
,SEQUENCE, 50, Close
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 機器をリモート状態（`GTR`）へ遷移させた直後、現在の実際の通信制御モードを検証して分岐処理を行いたいコンテキストです [1.2]。
*   **実行後の状態**: 通信対象デバイスの状態が瞬時に読み取られ、パターンマッチングを介して規定の文字列（例: `"Remote"`）へと高速変換されます [1.1]。変換された文字列は、格納先として指定された変数 `P_STATUS` へと安全にセットされます [1.1, 1.2]。対象デバイスオブジェクトが未生成である場合や引数が欠損している場合は、例外を発生させずに安全に処理がスキップされます [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **格納先パラメータ（引数1）が変数プールに存在しない場合**
    引数1で指定された変数キーがコマンドの `Params` 辞書に事前登録されていない場合、システムは不正なメモリ書き込みをスキップします [1.3]。ログへエラー（`LogError`）を排出し、マクロの実行コンテキストを維持したまま安全に該当ステップを終了します [1.3]。
*   **致命的例外が発生した場合（LogCritical）**
    デバイスステータスの読み出し時や文字列フォーマットの整形時に予期せぬ内部例外が発生した場合、`catch (Exception)` ブロックがすべてを安全に捕捉します [1.3]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、エディタUIや測定スレッド全体の強制終了を自動防御します [1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

| :--- | :--- | :--- | :--- | :--- |
| **1** | 正常系 | `status = RemoteStatusEnum.Local` | 戻り値: `"Local"` | `RemoteStatusEnum.Local` が `"Local"` という文字列に正しくマッピングされること。 |
| **2** | 正常系 | `status = RemoteStatusEnum.Remote` | 戻り値: `"Remote"` | `RemoteStatusEnum.Remote` が `"Remote"` という文字列に正しくマッピングされること。 |
| **3** | 正常系 | `status = RemoteStatusEnum.LocalLockOut` | 戻り値: `"Remote (Local Lock Out)"` | `RemoteStatusEnum.LocalLockOut` が `"Remote (Local Lock Out)"` という文字列に正しくマッピングされること。 |
| **4** | 正常系 | `status = RemoteStatusEnum.ReservLockOut` | 戻り値: `"Local (Reserv Local Lock Out)"` | `RemoteStatusEnum.ReservLockOut` が `"Local (Reserv Local Lock Out)"` という文字列に正しくマッピングされること。 |

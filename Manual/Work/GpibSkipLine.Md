# コマンドリファレンス：SkipLine

## 概要
`SkipLine` は、現在受信バッファ（`RecData`）内に保持されている複数行の文字列から、指定された行数分のテキスト（測定器の応答ヘッダー行や不要なログ行など）を一括して読み飛ばし（スキップ）、以降の解析のために有効な行データのみにバッファを切り詰めるデータ前処理系シーケンスコマンドです [1.1]。
複数行にわたる一括測定データや、独自のステータスヘッダー行がデータ本体の前に出力される波形アナライザ等の機器を制御する際、不要なテキスト行を安全に分離（剥離）するために使用します [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドは、解析パラメータ（`AnaParam`）内の共通受信バッファである `param.RecData` の中身を直接書き換える「インプレース（破壊的）クリーンアップ」を行います [1.1]。指定された行数分だけテキストの先頭を削り、残りの有効な行データで `param.RecData` を上書きします [1.1]。

---

## 💡 書式・パラメータ仕様

```csv
,SEQUENCE, [ステップキー], SkipLine, [スキップする行数]
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | スキップする行数 | 先頭から読み飛ばしたい不要なテキストの行数（1以上）。（必須引数） [1.1] | 固定値（例: `2`）またはパラメータ動的置換（例: `$P_SKIP$`） [1.1] |

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: 引数1において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.1]。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 本コマンドの引数は数値および変数キー指定を想定しているため、カンマのエスケープ規約は原則適用されません。

## 💡 動作例（正しい構文での記述例）

### データ前詰めの具体例と内部挙動
*   **初期の受信バッファ（`param.RecData`）の状態**:
    ```text
    [HEADER_START]
    DEVICE:MULTIMETER
    +1.2345E+00
    ``` [1.1]
*   **マクロの記述**: `,SEQUENCE, 30, SkipLine, 2` [1.2]
*   **内部での書き換え処理**:
    1.  `objLib.SkipLine(param.RecData, 2)` が実行されます [1.2]。
    2.  先頭の2行（`[HEADER_START]` と `DEVICE:MULTIMETER`）が正常にスキップ（読み飛ばし）され、有効なデータ行のみが抽出されます [1.2]。
    3.  受信バッファ（`param.RecData`）の内容が、切り詰められた `"+1.2345E+00"` へと上書き更新されます [1.2]。

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Header_Skip_And_Array_Flow"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_SKIP, Value, "不要行数", "2"
,PARAM, P_ARRAY, Work, "データ配列", ""
; 1. 測定クエリを送信し、複数行の生データを受信バッファへ回収
,SEQUENCE, 10, Send, "FETCH:ALL?"
,SEQUENCE, 20, Receive
; 2. 【行スキップ】変数(P_SKIP)で指定された「2行」分のヘッダーテキストを安全に読み飛ばし
,SEQUENCE, 30, SkipLine, $P_SKIP$
; 3. クリーンになったバッファ（数値のみの行）を、データ蓄積コマンドで安全に配列へ格納
,SEQUENCE, 40, SetData_RowAdd, P_ARRAY, "%s"
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 測定コマンドによって複数行のテキストデータが受信され、共通受信バッファに不要なヘッダー行を含む生データ文字列が保持されているコンテキストです [1.1, 1.2]。
*   **実行後の状態**: 指定された行数分だけテキストの先頭が削られ、残りの有効な行データで `param.RecData` が上書き更新されます [1.1, 1.2]。これにより、後続の `SetData_RowAdd` や配列操作コマンドがヘッダー行の存在を意識することなく、必要なデータ行から直接パースを開始できるようになります [1.1]。なお、スキップ行数に `0` が指定された場合は、バッファを書き換えずに処理をスキップします [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です [1.2]。

*   **必須引数の不足および空バッファ時の即時離脱**
    引数が1つも指定されていない（`sequence.Params.Count < 1`）場合、または受信バッファ（`RecData`）の内容が最初から空文字列（`string.IsNullOrEmpty`）であった場合は、無駄な処理を行わずに安全に処理をスキップ（早期リターン）します [1.2]。
*   **数値変換の失敗ガード（long.TryParse）**
    引数1に指定された文字列が整数に変換できない（`long.TryParse` に失敗した）場合、内部ログにエラー（`LogError`）を書き込み、バッファを書き換えることなく安全に処理を中断します [1.2]。
*   **パース結果が不正（Null）だった場合の安全保護**
    万が一 `SkipLine` の内部処理結果として `null` が返却された場合、バッファ構造を破壊させないよう、C# の null 合流演算子（`??`）を用いて安全な空文字（`string.Empty`）へと自動置換して格納します [1.3]。
*   **パース時等にシステム例外が発生した場合（LogCritical）**
    外部文字列制御ライブラリの行処理ロジック内で予期せぬ内部システム例外が発生した場合でも、`catch (Exception)` ブロックがすべての例外を確実に捕捉します [1.3]。詳細なスタックトレースをログに完全保存（`LogCritical`）し、アプリケーション全体の強制終了を自動防御します [1.3]。

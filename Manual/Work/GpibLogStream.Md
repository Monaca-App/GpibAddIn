# コマンドリファレンス：LogOut

## 概要
`LogOut` は、シーケンス実行中の外部計測データやログをファイルへストリーム出力するための「ファイルオープンの制御、上書き/追記設定、およびクローズ処理」を統合管理するシーケンスコマンドです [1.1]。
マルチスレッド環境におけるファイルロック競合や、バックグラウンド実行時のUIダイアログ呼び出しに伴うハングアップを回避するスレッドセーフな排他制御層を内蔵しています [1.1]。

> 💡 **補足 / ⚠️ 注意**
> 本コマンドは、渡される引数の数（パラメータ数）によって動作を自動的に切り替えます [1.1]。
> *   **引数あり（1個以上）の場合**: ログ出力の開始（ファイルの新規オープン / 追記オープン） [1.1]。
> *   **引数なし（0個）の場合**: ログ出力の終了（現在開かれているファイルリソースのクローズおよび `Dispose` 解放） [1.1]。

---

## 💡 書式・パラメータ仕様

### A. ログファイルを開く場合
```csv
,SEQUENCE, [ステップキー], LogOut, [出力先ファイルパス], [追記フラグ(true/false)]
```

### B. ログファイルを閉じる場合
```csv
,SEQUENCE, [ステップキー], LogOut
```

### パラメータ（引数）一覧

| 引数位置 | 引数名 | 説明 | 指定方法 / 有効な入力値 |
| :--- | :--- | :--- | :--- |
| **引数1** | 出力先ファイルパス | ログを書き込むファイルの絶対パス。省略または空文字時はダイアログを表示 [1.1]。 | 固定パス、またはパラメータ動的置換（例: `$P_PATH$`） [1.1] |
| **引数2** | 追記フラグ | 既存ファイルがある場合の動作。省略時は `false` [1.1]。 | `true`（追記）/ `false`（上書き確認） [1.1] |

※ファイルを閉じる場合は、引数1・引数2の指定は不要（空欄）です [1.2]。

---

## 🔄 特殊置換規約・分岐規約の適用

本コマンドの引数における、独自スクリプトの特殊記法の適用ルールです。

*   **動的置換（`$`）**: すべての引数において、`$PARAMキー$` のようにパラメータキーの両端を `$` で囲むことで、実行時に変数プール（`PARAM`）の値へと動的にパース展開・値置換されます [1.2]。これにより、品種名や現在日付を埋め込んだファイルパスを動的に生成してログを開始することが可能です [1.2]。
*   **条件ジャンプ（`#`）**: 本コマンドはジャンプ処理を行わないため、引数内での `#` によるステップキー指定は使用しません [1.2]。
*   **カンマのエスケープ**: 出力先ファイルパス文字列自体にカンマを含める場合は、構文エラーを防ぐため必ず `","` と二重引用符で囲んで記述する必要があります。

## 💡 動作例（正しい構文での記述例）

### スクリプト記述例
> ⚠️ **記述ルール注意**
> COMMANDブロック配下のため、子要素行（`PARAM`, `SEQUENCE`）は必ず行頭カンマから開始し、スペースインデントや行末コメント（`;`）は記述しないでください [1.1, 1.2]。コメントを入れる場合は、必ず独立したコメント行（行頭 `;`）を前に挟んでください [1.2]。

```csv
COMMAND, "Data_Logging_Run"
; コメントは独立した行に記述（行末への記述は完全禁止）
,PARAM, P_PATH, Text, "保存パス", ""
,PARAM, P_BUF, Work, "計測バッファ", ""
; 1. 変数(P_PATH)に指定されたパスでログファイルをオープン（空ならダイアログ自動起動）
; ※既存ファイルがあれば、上書き確認のメッセージボックスが表示されます
,SEQUENCE, 10, LogOut, $P_PATH$, false
; 2. 測定ループの開始
,SEQUENCE, 20, Send, "READ?"
,SEQUENCE, 30, Receive
,SEQUENCE, 40, SetData, P_BUF, "%s"
; 3. 【システム連携】取得した計測バッファの内容をファイルへ1行書き込み
; （内部C#インフラ層の GpibLogStream.WriteLog 処理等と自動連動します）
; 4. すべての測定が完了したため、ログストリームを安全にクローズしてリソースを完全解放
,SEQUENCE, 100, LogOut
```

### 実行時の挙動・変数変化

*   **実行前の状態**: 測定シーケンスが開始される直前、あるいは一連の連続データ回収が完了してファイルストリームを閉じる直前のコンテキストです [1.2]。
*   **実行後の状態**: 引数がある場合は、指定されたパス（またはUIスレッドを介した `SaveFileDialog`）を通じて出力先ファイルストリームが開かれます [1.1, 1.2]。引数がない場合は、現在開かれているファイルリソースが解放（`Dispose`）されてストリームが安全にクローズします [1.1, 1.2]。静的なロックオブジェクト（`_lock`）および非同期実行時の `InvokeRequired` 判定により、ファイル競合やUIフリーズを発生させずに安全に処理されます [1.1]。

## 🚫 エラーハンドリング・安全設計（仕様制限）

入力データの異常や記述ミスに対し、解析・実行エンジンが実行するセーフティ規約です。

*   **ファイルパス（引数1）が未指定・空文字の場合**
    `SaveFileDialog` が自動的に起動します [1.3]。作業者がダイアログで「キャンセル」を選択した場合は、ストリームを開かずに安全に該当ステップをスキップ（早期リターン）します [1.3]。
*   **同名ファイルが存在する場合のインテリジェントな挙動（引数2が `false` 時）**
    上書き確認のダイアログ（`Yes/No/Cancel`）がメインフォーム側で安全にポップアップ表示されます [1.1, 1.3]。
    *   `[Yes]`: 既存ファイルを削除して完全新規上書き [1.3]。
    *   `[No]`: 既存ファイルの末尾にデータを追加（自動で追記モードへ切り替え） [1.3]。
    *   `[Cancel]`: 処理を中断して安全にステップをスキップ [1.3]。
*   **書き込みエラー発生時の自動クローズ保護（WriteLog 内）**
    ディスク満杯やネットワーク切断等により、`_logWriter.WriteLine` で例外が発生した場合、システムは即座にエラーログ（`LogCritical`）を保存し、自動的に内部で `CloseLog()` を呼び出して壊れたハンドルを安全に破棄します [1.3]。これによりメモリリークやアプリケーションの停止を防止します [1.3]。

## 🧪 ユニットテスト仕様

本コマンドクラスに実装されている `RunUnitTest()` メソッドが検証するユニットテストの仕様です。

### テスト実行前提条件
* **実行トリガー**: `RunUnitTest()` メソッドの呼び出し
* **有効化条件**: システム全体の最小ログレベル（`ErrorLogger.MinimumLevel`）が `LogLevel.Test` であること（それ以外の場合は無効化ガードにより即座に早期リターン）
* **検証結果出力**: `ErrorLogger.LogTest` によるログ出力。検証失敗時は `ErrorLogger.LogError`、予期せぬ例外発生時は `ErrorLogger.LogCritical` で記録

## 📖 概要

**GpibAddIn** は、Microsoft Excel のワークシート上から GPIB 接続された電子計測機器・電源・各種デバイスの制御シーケンスを構築・実行・データ収集できる Excel VSTO アドインです。

プログラミング言語による面倒なコーディングやマクロ（VBA）の開発を行うことなく、**使い慣れた Excel のセルにコマンドとパラメータを入力するだけ**で、機器へのコマンド送信、待機時間（ウェイト）、測定値のセル自動展開、一括シーケンス実行がすべて Excel 上で完結します。

> [!IMPORTANT]
> ### 💡 本アドイン最大の設計思想・特長
> **「VBAマクロに一切依存せず、VSTO側からActiveXコントロールを動的バインドすることで、標準のマクロ無効ブック形式（`.xlsx`）のままでシーケンスボタンを配置・保存・動作できる」**
> 
> * **セキュリティ警告・ブロックの完全回避**: 近年の Windows / Office 環境ではマクロ有効ブック（`.xlsm`）に対するセキュリティ制限（信頼できない発行元のブロック、インターネット属性・MOTW によるマクロ強制停止等）が極めて厳格化されています。本アドインはブック側に一切のマクロ（VBA）を含まないため、**標準の `.xlsx` ファイルとして何らセキュリティ警告を受けることなく安全に作成・保存・運用・社内共有** できます。
> * **VBE・マクロ保守の手間ゼロ**: Excel のバージョン差異による VBE 参照設定エラーやマクロコード破損のリスクがなく、長期にわたる測定システムの安定稼働を実現します。

## ✨ 主な機能・特徴

### 1. VBAマクロ完全非依存 ＆ 標準 `.xlsx` での完全動作
* 本アドイン最大の強みとして、Excel シート上に動的配置されるコマンド実行ボタン（ActiveX ボタン）の制御・イベントハンドリングはすべてアドイン（VSTO / .NET）側から動的にバインド・制御されます。
* そのため、ブックをマクロ有効形式（`.xlsm`）に変換することなく、**普段使いの標準的な `.xlsx` 形式のままシーケンスボタンの配置・保存・実行がすべて完結** します。マクロの実行許可設定やセキュリティポリシーに縛られない、極めて高い利便性と安全性を両立しています。

### 2. マルチベンダー対応（GPIBドライバ）
* CONTEC 製ボード（`CGPIB.dll`）および Interface 製ボード（`GPC4304.dll`）の両ドライバに対応し、メイン画面のメニュー（[環境設定...] ➔ [CONTEC] または [Interface]）からワンクリックで、環境や保有ハードウェアに合わせて柔軟に切り替え可能です。
* メイン画面のメニュー（[環境設定...] ➔ [Debug]）を有効にすることで、実機ハードウェアやドライバー DLL が存在しない環境でも完全な動作シミュレーションが可能です（実機やGPIBボード、各メーカー提供ドライバーがないPCでも、シーケンス作成やUI連携テストを行えます）。

### 3. 複数台接続＆機能特化型CSVの柔軟な混在運用
* **同型機の複数台マルチ接続（台数分ロードで自動連番）**:
  * 同じ計測器を複数台接続して同時に自動測定を行う場合、同一の CSV 定義ファイルを**接続する台数回読み込ませるだけ**で準備完了です。
  * システムが自動的に `01`〜 の連番（例: `HP_34401A_01`, `HP_34401A_02`...）を付与して重複なく明確に区別・管理します。あとはプロパティ画面でそれぞれの機器を選択し、実機ハードウェアに設定されている個別のアドレス（プライマリアドレス等）を指定して「通信詳細設定」で登録するだけで、複数台の並行制御が即座に可能になります。
* **1台の機器に対する機能特化型 CSV 運用（同一アドレス指定）**:
  * 1つの計測器に対して、機能や用途ごとに特化した複数の CSV ファイル（例: 電圧測定用、電流測定用、波形解析用など）を用意して個別に読み込ませることも可能です。
  * その際は、プロパティ画面でそれぞれの定義に対し、実機のアドレスを指定して「通信詳細設定」で同一のアドレスを登録するだけで、高機能な計測器のコマンド群を目的に応じてスマートに分割・整理して運用できます。
* **自由自在なハイブリッド混在運用**:
  * 「複数台の同型機接続（01〜）」と「機能特化型 CSV（同一アドレス）」を**1つのシステム・シート内で自由に混在させて運用**できます。複雑な検査ラインや多チャンネル自動計測システムでも、CSV の組み合わせと「通信詳細設定」のアドレス登録だけで直感的かつ柔軟に構築可能です。

### 4. セル単位でテストシーケンスを簡単構築
* リボンメニューの「シーケンス作成」をクリックするだけで、コマンド実行ボタン・ウェイト・コマンド名・結果セル・パラメータ枠がシート上に自動生成されます。
* リスト型のパラメータ（レンジ切り替えやモード選択など）には Excel の入力規則（ドロップダウンリスト）が自動適用され、入力ミスを防ぎます。

### 5. 単発実行 ＆ 一括自動実行
* **個別実行:** 各コマンド行の左端にある「実行」ボタン（ActiveX ボタン）をクリックすれば、その行のコマンドだけを単体テストできます。
* **一括実行（Start）:** 「一括実行ボタン配置」で生成される Start ボタンを押すだけで、指定した開始行から下に向かって定義されたシーケンスを順番に自動実行します。

### 6. 計測データのリアルタイム・自動セル展開
* 機器からの取得データは、シーケンス行の結果セル（Result列）へリアルタイムに書き込まれます。
* 複数データや二次元配列データ（オシロスコープの波形データや多点計測値など）は、指定セルを起点として縦横のセル範囲へ自動的に展開されます。

### 7. セル装飾・スタイルの自動保存＆テンプレート化
* セルの背景色、罫線（太さ・線種・色）、フォント、列幅、配置などを自分好みにデザインしたあと、「スタイル保存」ボタンを押すだけでテンプレートとして設定ファイルへ保存されます。
* 次回以降の「シーケンス作成」時には、保存されたお好みのスタイルが自動適用されます。

### 8. 完全なファイル互換性（ライセンス無PC作成Excelのシームレス動作）
* ライセンスの無いPC（評価版環境や出張先・テレワーク用ノートPC等）で作成・編集したExcelファイル（シーケンスシート）であっても、**ライセンスの有るPC（本番測定PCや検査ライン等）で開けば、一切の制限なくそのまま問題なく動作・実機自動測定が可能**です。
* シーケンスデータは標準のExcelセル情報として保持されるため、ライセンスの有無によるファイルロックや破損等の心配がなく、「自席のノートPCでシーケンスを作成・シミュレーション検証し、検査ラインのライセンスPCで本番実行する」という柔軟な分業・運用を実現できます。

### 9. 多言語UI対応（日本語 / 英語 / 自動判別）
* メイン画面のメニュー（[環境設定...] ➔ [環境設定]）から、画面表示言語を **「日本語」「英語」「自動判別（OS設定準拠）」** から自由に切り替え可能です。
* 言語を切り替えると、メイン画面・エディタ画面・プロパティ設定画面・Excelリボンメニューの表示ラベルがリアルタイムに即座に更新され、設定は次回起動時も保持されます。海外拠点やグローバル開発環境でもそのままご利用いただけます。

### 10. 通常 Excel ファイルの高速オープン・オーバーヘッド防止（除外キャッシュ）
* `.csv` やテキスト形式等の非ブック形式は走査を一切行わず **0ms で即座にスキップ** します。
* 本アドインの標準対応形式である `.xlsx`（マクロ無効形式）や `.xlsm` であっても、
  シーケンスボタンを持たない無関係な通常ファイルは除外キャッシュ
  （`%USERPROFILE%\Desktop\Monaca\GpibAddIn.IgnoredWorkbooks.txt`）に自動登録され、
  2回目以降のオープン時の走査を完全に防止します（キャッシュファイルを削除すればいつでも手動リセット可能）。

### 11. 設定変更履歴の自動記録（安心設計・トレーサビリティ保証）
* 誤った機器設定の早期発見や検査ラインでの安心運用のため、通信パラメータや環境設定を変更して
  保存した際、変更前後の内容が自動的に監査ログファイルへ記録されます。
* ログの保存先フォルダやファイル名は、メイン画面のメニュー（[環境設定...] ➔ [エラー履歴]）から
  自由に変更・確認が可能です（既定はデスクトップの `Monaca\info.log`）。
* 過去にどのような設定変更が行われたかを後から確実にトレースできるため、複数人で共有運用する
  測定環境でも安心してご利用いただけます。

## 📊 シート上のシーケンス構成

アドインで作成されるシーケンス行は、シートの特定列（A列など）に固定されるのではなく、**選択したセル（指定セル）を先頭として、その行に横方向へ連続配置**されます（縦2行分で1つのシーケンスコマンド行を構成）。

| セル位置 | 先頭セル（基準） | +1列 | +2列 | +3列 | +4列 | +5列以降 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **役割** | **Label (実行)** | **Wait (待機)** | **Command** | **Result (結果)** | **Param 1** | **Param 2...** |
| **上段セル**<br>*(項目名/Help)* | — | 待機時間(ms) | コマンド名 | 取得結果 | パラメータ名 | パラメータ名 |
| **下段セル**<br>*(設定値/ボタン)* | **[ 実行 ]**<br>*(ActiveX)* | `500` | `MEAS_VOLT` | `12.345 V` | `CH1` | `10V` |

<br>

| 相対位置 | 項目 | 役割・動作 |
| :---: | :--- | :--- |
| **先頭セル（基準）** | **Label (実行ボタン)** | クリックすることで、その行に記述されたコマンドを単発実行します。 |
| **+1列** | **Wait (待機時間)** | コマンド実行前のウェイト時間（ミリ秒）を指定します。機器の安定待ちに利用します。 |
| **+2列** | **Command (コマンド)** | 実行対象の制御コマンド名（マクロ定義名またはGPIBコマンド）を指定します。 |
| **+3列** | **Result (結果出力)** | 機器から返却されたレスポンスや測定値の出力先（セル番地または名前定義）を指定します。 |
| **+4列以降** | **Parameter (パラメータ)** | コマンドに渡す設定値（電圧値、レンジ、チャンネル等）を入力・選択します。 |

### 💡 Result（結果出力セル）の仕様と運用上の重要な注意点

コマンド実行によって機器から返却された測定データやレスポンス文字列は、**+3列目の下段セル（Result設定セル）に指定されたターゲット位置へ自動的に書き込まれます**。運用にあたっては以下の動作仕様と注意点をご確認ください。

1. **出力先リストの自動表示（データ出力コマンド時）**:
   * コマンド定義にデータ出力（`ResultItem`）が設定されている場合、シーケンス配置時にブック内の名前定義をスキャンし、**出力先候補となる名前付きセルの選択ダイアログ**が自動表示されます。
2. **未選択時の動作（セル番地自動設定）**:
   * ダイアログでリストから何も選択せずに [OK]（または [キャンセル]）をクリックした場合、**そのシーケンス行の結果セル自身のアドレス（例: `D10` など）** が下段セルに自動設定されます（この場合、実行結果はその行の結果セル自身に表示されます）。
3. **名前付きセルの事前準備（推奨）**:
   * Excel の標準機能（[数式] ➔ [名前の定義]）を使って測定値の記録先セルに名前（例: `測定電圧_CH1` や `Log_Current` 等）をあらかじめ定義しておくと、配置時のリスト上に表示され、クリックするだけで出力先として紐付けられます。
4. **後からの手動直接入力・変更も可能**:
   * シーケンスを配置した後でも、下段セル（Resultセル）の値は Excel 上で直接キーボードから編集可能です。任意のセル番地（例: `F20`）や新しく定義した名前文字列を直接書き込むだけで、出力先をいつでも自由に変更できます。
5. **⚠️ セル名（番地文字列）運用における注意点（名前付きセルの推奨理由）**:
   * 下段セルに `"B10"` のような通常のセル番地（文字列）を設定している場合、**シート上で行や列の挿入・削除を行うと、セル内の文字情報自体は自動変更されず `"B10"` のまま残るため、本来意図していた出力先から位置がズレてしまう**現象が発生します。
   * **「名前付きセル」で出力先を指定しておけば、シート上で行や列の挿入・削除・移動が行われても Excel が自動的にセルの位置を追従するため、測定値が常に正しいセルへ確実に記録されます。長期的な検査シートの保守や行追加を想定する場合は、「名前付きセル」による運用を強く推奨します。**

## 🖥️ メイン画面機能（ドライバー切替とシミュレーション）

Excel リボンメニューの **「ツール起動 (`ToolOpen`)」** ボタンから呼び出せるメイン画面のメニューバー **[環境設定...]（英語表記: [Settings...]）** から、使用する GPIB ドライバーのメーカー選択や、動作シミュレーションモードの切り替えを画面上から直接操作できます。

```
[環境設定... / Settings...]
  ├── 環境設定（システム環境設定ダイアログ）
  ├── エラー履歴（エラー履歴ダイアログ）
  ├── ---------------------------- (セパレータ)
  ├── [✔] CONTEC
  ├── [ ] Interface
  └── [✔] Debug
```

### 1. CONTEC / Interface（ドライバーメーカー切替）
* **機能**: 使用する GPIB ドライバー（CONTEC 社製 `CGPIB.DLL` / Interface 社製 `gpc4304.dll`）をメニューから直接切り替えます。
* **仕様**: 排他選択（どちらか一方のみチェック）となっており、選択したメーカーのドライバーへ即座に切り替わり自動保存されます。
* **安全性**: 実機モード（Debug が OFF）の際に対象ドライバー DLL が存在しない場合は警告ダイアログが表示され、デバッグモード（シミュレーション）で安全に切り替えるか選択できます。また、通信ポートが開いている（接続中）状態では誤動作防止のため切り替えはブロックされます。

### 2. Debug（デバッグ動作・シミュレーションモード切替）
メニューの **[環境設定...] ➔ [Debug]** のチェックを切り替えることで、**GPIB ボードや実機計測器が接続されていない PC 環境でもデバッグ動作・シミュレーションが可能**になります。

* **用途**:
  * 実機や GPIB ボードがない開発用 PC やオフィス PC での動作確認
  * Excel 上でのシーケンス構築、リボンメニューの動作、ボタン配置やセル展開などの UI 連携テスト
* **動作仕様**:
  * メニューの [Debug] を有効（ON）にすることで、物理的な GPIB API（DLL）の呼び出しを安全にバイパスし、実機ハードウェアや各メーカー提供のドライバー（DLL）がインストールされていない PC 環境であっても、DLL 呼び出しを内部で安全にエミュレートし、擬似データを受信・展開してシーケンス処理をシミュレーション実行できます。
  * 実機制御を行う本番環境ではチェックを外して無効（OFF）にして運用してください。
* **安全性**:
  * チェックを外して実機モードに戻そうとした際、対象 DLL がシステムにインストールされていない場合はエラー通知を表示して実機切り替えを安全に防御します。
  * 通信ポートが開いている（接続中）状態での切り替えはブロックされます。
### 3. 接続時刻表示（通信ログ タイムスタンプ付加）
メニューの **[時刻表示] ➔ [時刻有効] / [時刻無効]** から、送受信データログの各行の先頭にミリ秒精度のタイムスタンプ（`[ yyyy/MM/dd HH:mm:ss.fff ]`）を付加してリアルタイム表示・記録するかどうかを切り替えることができます。

### 4. バージョン情報確認（オフライン完全対応）
メニューの **[ヘルプ] ➔ [バージョン情報...]** を開くことで、現在稼働しているアプリケーションの正式バージョン番号（例: `Version 0.9.1.0`）、著作権情報、および動作環境（.NET Framework / OS 情報）をダイアログで確認できます。外部インターネット接続を一切行わないため、工場や研究所のオフラインPCでも安心してご利用いただけます。

### 🖥️ 高解像度（高DPI）モニタ環境における推奨事項・制限事項

* **UIレイアウトの最小サイズ制約**:
  * メイン画面および各種設定ダイアログは、高DPIスケーリング環境下でも各操作ボタンやステータスLEDインジケータ（8連ランプ）の視認性を確保するため、最小ウィンドウ幅を **`500px × DPIスケール比率`**（クライアント幅 `484px × DPIスケール比率`）に制限しています。

* **異なる拡大率のマルチモニタ環境での注意事項**:
  * スケーリング倍率の異なる複数ディスプレイ間（例: 4Kモニタ 150% と フルHDモニタ 100%）を跨いでウィンドウをドラッグ移動した場合、Windows および Office の再描画タイミングにより、一時的な表示のちらつきや、Excel シート上の ActiveX ボタン配置・フォント描画にわずかなズレが生じる場合があります。
  * **対処方法**: ウィンドウを一度最大化/元に戻すか、Excel 側で一時的な描画乱れが発生した場合は Excel を再起動するか「互換性を優先する」表示設定をご利用ください。

5. **機器情報の登録**: **「プロパティ」タブ** に戻り、制御対象の機器情報（機器名称、GPIBアドレス、デリミタ等）を設定して **「確定」** をクリックします。

>   * その際は、プロパティ画面でそれぞれの機器定義に対し、画面上で同一のアドレス（プライマリアドレス等）を指定し、「通信詳細設定」ボタンをクリックして登録情報を更新してください。
> * **混在運用**:
>   * これら（複数台の同型機 × 機能特化型CSV）を混在して運用することも可能です。

### ステップ 2: シーケンス行の追加
1. 新規または既存の Excel ワークシートを開きます。
2. シーケンスを配置したい開始セル（例: `A5` や任意のセル）を選択します。
3. リボンメニューの **「シーケンス配置 (Make_Sequence)」** をクリックします。

1. **コマンドセル**: 実行したい機器コマンドを選択または入力します。

* 行頭の **[ 実行 ]** ボタンをクリックします。

3. **Start** ボタンをクリックすると、シーケンスが上から順に自動実行され、測定結果が次々とシート上に記録されます。

## 📜 GPIBマクロスクリプト (CSV定義ファイル)

GpibAddIn で実行される制御コマンドや機器定義は、独自の階層構造を持つ **CSV 形式ファイル（Shift-JIS）** によって定義されています。  
新しい計測機器の追加や独自シーケンスの作成も、CSV ファイルを記述・登録するだけでプログラムの再ビルドなしに Excel から利用可能になります。

### 1. 階層構造と構文ルール
解析エンジンは行頭（第1フィールド）の記述状態によって、親ブロックと子要素（サブコマンド）を自動判別します。

* **親ブロック（行頭から記述）**:
  * `TITLE, "[機器名称]"`: 対象機器のハードウェア構成宣言
  * `COMMAND, "[コマンド名]", "[結果格納先キー]"`: マクロコマンドの定義宣言
* **子要素・サブコマンド（行頭カンマ `,` から記述）**:
  * `,DEVICEBOARD, [ボード番号]`: 使用するGPIBボード番号
  * `,DEVICEADDRESS1ST, [アドレス]`: 機器のプライマリアドレス（0〜30）
  * `,DELIMITER, [識別子]`: 終端文字（0: なし, 1: CRLF, 2: CR, 3: LF）
  * `,PARAM, [キー], [データ型], [表示名], [初期値/選択肢...]`: コマンド引数の定義
  * `,SEQUENCE, [ステップ], [マクロ名], [引数...]`: 実行する処理手順（Send, Receive, Wait, 計算, 分岐等）

### 2. PARAM（パラメータ）のデータ型と Excel 連携
`PARAM` で指定されたデータ型に応じて、Excel シート上での UI 動作が自動連動します。

| データ型 | 挙動・Excel上の動作 |
| :--- | :--- |
| **`Text`** | 汎用テキスト入力。自由な文字列や数値を入力できます。 |
| **`List`** | ドロップダウンリスト。定義された選択肢が Excel の「データの入力規則」としてセルへ自動適用されます。 |
| **`Range`** | 測定結果展開用。受信したカンマ・改行区切りの配列データを、Excel セルへ縦横 2次元自動展開します。 |
| **`Value`** | 数値検証付きの入力スタイル。 |
| **`Work`** | マクロ内部の一時メモリ・バッファとして利用される領域。 |

### 3. 複数台接続＆機能特化型運用の仕様

本アドインは、現場の様々な測定ニーズ・ハードウェア構成に柔軟に対応できるよう設計されています。

#### ① 同じ計測器を複数台つなぐ場合（自動連番ナンバリング）
* 同型番のデジタルマルチメータや電源を2台、3台と複数台接続して使用する場合、**同じ CSV 定義ファイルを台数分（台数回）読み込ませてください**。
* システムが自動的に `01`〜 の連番サフィックス（例: `34401A_01`, `34401A_02`...）を付与し、重複することなく別々のデバイスとして登録・区別します。
* プロパティ画面にて、それぞれの機器（`_01`, `_02`...）を選択し、画面上で**実機ハードウェアに設定されている個別のアドレス（プライマリアドレス等）を指定し、「通信詳細設定」ボタンをクリックして登録情報を更新**するだけで、各機器を独立して制御できます。

#### ② 1つの計測器に対し機能特化型 CSV ファイルを用意する場合（同一アドレス指定）
* 1つの計測器に対して、用途や測定機能ごとに特化させた複数の CSV ファイル（例: 電圧測定用、電流・抵抗測定用、キャリブレーション用など）を用意して読み込ませることも可能です。
* その際は、プロパティ画面でそれぞれの登録定義を選択し、画面上で**同一のアドレス（プライマリアドレス等）を指定し、「通信詳細設定」ボタンをクリックして登録情報を更新**してください。
* コマンドの選択肢が整理され、Excel シート上でのシーケンス作成時にも目的のコマンドを迷わず選択できるようになります。

#### ③ 自由なハイブリッド混在運用
* 「複数台接続（01〜連番）」と「機能特化型 CSV（同一アドレス）」を**1つのシート・システム内で自由に混在させて運用**することも可能です。

* **運用実例（名前生成規則とアドレス設定の流れ）**:
  * **機器1（電源・アドレス 1）**:
    * `POWER_MAIN.csv` を用いて自動生成名 **`POWER_MAIN_01`**（アドレス `1` を指定して更新）
  * **機器2（マルチメータ1台目・アドレス 22）**:
    * `DMM_VOLT.csv`（電圧機能特化CSV）を用いて自動生成名 **`DMM_VOLT_01`**
    * `DMM_FREQ.csv`（周波数機能特化CSV）を用いて自動生成名 **`DMM_FREQ_01`**
    * ※上記2つの定義に同一のアドレス `22` を指定し、「通信詳細設定」ボタンで登録情報を更新
  * **機器3（マルチメータ2台目・アドレス 23）**:
    * `DMM_VOLT.csv`（電圧機能特化CSV）を再度用いて自動連番で **`DMM_VOLT_02`**
    * ※個別のアドレス `23` を指定し、「通信詳細設定」ボタンで登録情報を更新

このような高度で柔軟な測定ラインの構築も、プロパティ画面での簡単な操作だけでスムーズに実現できます。

## ⚙️ 設定ファイル (`Setting.xml`)

アドインのスタイル設定や通信設定は、以下の設定ファイルにて一元管理されています。

* **設定ファイルパス**: `%USERPROFILE%\Desktop\Monaca\Setting.xml`（`C:\Users\<ユーザー名>\Desktop\Monaca\Setting.xml`）
  * ※ デスクトップ上の `Monaca` フォルダがデフォルトの配置先となります。
  * ※ 購入後にメール（送信元: `sales@monaca-app-store.com`）で届くライセンスファイル（`GpibAddIn.License`）も本設定ファイルと同じフォルダ（`%USERPROFILE%\Desktop\Monaca\`）に配置します。
* **主な設定項目**:
  * `GpibAddIn_Styles`: 各セルの背景色、罫線スタイル、文字配置、列幅等の装飾テンプレート情報
  * `Command`: 制御対象機器とコマンド定義ファイル（CSV/XML）の関連付け
  * `DLLType`: 使用するドライバーメーカー（`DLLMaker`）および動作シミュレーション設定（`DebugDLL`）。※メイン画面のメニューから直接切り替え・保存されます。
  * `Setting` (`Language`): UI 表示言語コード（`""` = 自動判別、`"ja-JP"` = 日本語、`"en-US"` = 英語）
  * `Log`: 通信ログの出力先ディレクトリおよびログレベル
* **除外キャッシュファイル (`GpibAddIn.IgnoredWorkbooks.txt`)**:
  * `Setting.xml` と同じディレクトリに自動生成され、シーケンスボタンを持たない通常 Excel ファイルのパスを保持して起動オーバーヘッドを防止します（ファイルを削除することで手動キャッシュクリアが可能）。

#### 🔍 PC_Name および User_Name の確認方法

お支払い画面（Stripe）のカスタムフィールドに入力する `PC_Name` と `User_Name` は、以下の手順でご確認いただけます。**大文字・小文字やスペルミスを防ぐため、コマンドによる確認を推奨いたします。**

##### 方法1：コマンドプロンプト / PowerShell で確認（推奨・最も確実）
1. キーボードの `Windows キー` を押し、`cmd`（または `powershell`）と入力して起動します。
2. 以下のコマンドを入力して `Enter` キーを押します：
   ```cmd
   whoami
   ```
3. 画面に **`PC名\ユーザー名`**（例: `DESKTOP-ABC1234\taro`）の形式で出力されます：
   * **`\` の手前** ➔ **`PC_Name`**（例: `DESKTOP-ABC1234`）
   * **`\` の後ろ** ➔ **`User_Name`**（例: `taro`）

> [!TIP]
> 個別に確認・コピーしたい場合は、以下のコマンドも利用可能です：
> * PC名のみ確認: `echo %COMPUTERNAME%`（または `hostname`）
> * ユーザー名のみ確認: `echo %USERNAME%`

##### 方法2：Windows の「設定」画面から確認
* **`PC_Name`**: 「スタート」ボタンを右クリック ➔「システム」を選択（または「設定」➔「システム」➔「バージョン情報」）し、画面に表示される **「デバイス名」** をご確認ください。
* **`User_Name`**: 「スタート」メニューを開いたときに表示される現在のアカウント名です。  
  *(※ Microsoft アカウントと連携している場合、表示名と Windows 内部の実際のログインユーザー名が異なる場合があります。そのため方法1の `whoami` による確認を強く推奨します)*
